The OTP (one-time-password) input is the row of little boxes you meet at every 2FA / sign-in-code / phone-verification screen: six separate single-character fields that feel like one. The craft is entirely in the behaviour. Typing a digit auto-advances to the next box; Backspace on an empty box jumps back and clears the previous one; the ← / → arrows walk between boxes; and — the part people always get wrong — pasting a full 123456 splits one digit per box instead of dumping the whole string into one field. Only digits are allowed in, and the instant the sixth box fills, an on-complete event fires that validates the code and flips the whole field green. There is a resend countdown and real ARIA underneath. Try it below — type, paste the demo code, hit Backspace, and watch the read-out on the right update live.

🔨 Build it yourself

    
An OTP input is N single-character text fields in a row that behave like one. The layout is a flex row of tiny <input>s; the real work is the behaviour that makes them feel like a single field: digit-only filtering, auto-advance, the backspace-goes-back rule, arrow-key movement, paste-splitting, a single complete event, validation, a resend timer, and real ARIA. We build all of it from scratch over six boxes, one piece at a time, no framework and no dependencies.

    
    
      
  1. 
        
    1
    The boxes — render N inputs from a single number
    
        
    Do not hand-write six <input>s — render them from one LEN constant so the field is trivially 4, 6 or 8 boxes. Each is a real text input with maxlength="1", and the hints that make phones behave: inputmode="numeric" pops the number pad, autocomplete="one-time-code" lets iOS/Android offer the SMS code, and a data-i index tells every handler which box it is. Keep a live array of the DOM nodes in boxes — every other step indexes into it.
    
        
    const LEN = 6;
otp.innerHTML = Array.from({length: LEN}, (_, i) => `
  <input class="otp-box" type="text" inputmode="numeric"
         autocomplete="one-time-code" maxlength="1"
         data-i="${i}" aria-label="Digit ${i+1} of ${LEN}">`
).join("");
const boxes = [...otp.querySelectorAll(".otp-box")];
const code  = () => boxes.map(b => b.value).join("");
    
      
    2. 
      
  2. 
        
    2
    Only digits get in
    
        
    A verification code is digits, so scrub everything else on the input event: value.replace(/\D/g, "") strips letters and symbols the instant they appear, so a stray "a" never sticks. Do it in JS rather than trusting type="number" — number inputs allow e, +, - and a spinner you do not want. If more than one digit landed in a single box (autofill, or a fast paste that slipped past step 7), don't throw the extras away — hand them to the spread helper so they flow into the following boxes.
    
        
    function onInput(e){
  const b = e.target, i = +b.dataset.i;
  let v = b.value.replace(/\D/g, "");   // DIGITS ONLY
  if (v.length > 1) return spread(v, i); // multi-char -> flow across boxes
  b.value = v;
  if (v && i < LEN - 1) boxes[i + 1].focus();  // auto-advance (step 3)
  afterChange();
}

  3. 
        
    3
    Auto-advance on entry
    
        
    The signature feel: type a digit and focus jumps to the next box so the user just keeps typing without ever reaching for Tab. It is one line inside onInput — if a digit was entered and we are not already on the last box, boxes[i + 1].focus(). Because each box is maxlength="1", it can only ever hold that one digit, so the next keystroke naturally lands in the box you just moved to. On the last box you deliberately do not advance — there is nowhere to go, and that is where completion is detected (step 8).
    
        
    // inside onInput, after writing the digit:
if (v && i < LEN - 1) boxes[i + 1].focus();
// last box: no advance -> caret stays, completion check runs
    
      
    4. 
      
  4. 
        
    4
    Backspace: delete, or jump back and clear
    
        
    This is the rule everyone gets wrong. Backspace has two jobs depending on the box's state, handled in keydown (so we act before the value changes). If the current box has a digit, let the default delete it in place. If it is already empty, the user wants to fix the previous box: preventDefault(), move focus back one, and clear that box too — so one Backspace both jumps and erases, exactly like a real single field. Without this, backspacing from an empty box does nothing and the user is stuck.
    
        
    function onKeydown(e){
  const i = +e.target.dataset.i;
  if (e.key === "Backspace" && e.target.value === "" && i > 0){
    e.preventDefault();
    boxes[i - 1].focus();        // jump back
    boxes[i - 1].value = "";     // and clear it
    afterChange();
  }
  // box has a value -> default Backspace clears it in place
}
    
      
    5. 
      
  5. 
        
    5
    Arrow-key navigation (← →)
    
        
    A keyboard user must be able to move without retyping. In the same keydown handler, ← focuses the previous box and → the next, each guarded so you cannot walk off either end, and each with preventDefault() so the arrow does not also move the caret inside the one-char field. This costs two lines and turns the six boxes into something you can actually navigate — pair it with a focus handler that selects the box's content so typing overwrites instead of appending.
    
        
    if (e.key === "ArrowLeft"  && i > 0)       { e.preventDefault(); boxes[i-1].focus(); }
if (e.key === "ArrowRight" && i < LEN-1)   { e.preventDefault(); boxes[i+1].focus(); }

// so typing replaces instead of appends:
boxes.forEach(b => b.addEventListener("focus", () => b.select()));
    
      
    6. 
      
  6. 
        
    6
    Paste a whole code — split it across the boxes
    
        
    Real users copy the code from their SMS or email and paste it. The naive field dumps all six digits into one box; the correct one spreads them. Listen for paste, preventDefault() so the browser's default single-box insert never runs, read the clipboard text, keep only its digits, and write one per box from the start. A shared spread() helper does the writing and is reused by step 2's multi-char guard, so paste and fast-typing behave identically. Then move focus to the box after the last one filled, and run the change hook.
    
        
    function spread(str, start = 0){
  const ds = str.replace(/\D/g, "").split("");
  for (let k = 0; k < ds.length && start + k < LEN; k++)
    boxes[start + k].value = ds[k];
  const landed = Math.min(start + ds.length, LEN - 1);
  boxes[landed].focus();
  afterChange();
}
otp.addEventListener("paste", e => {
  e.preventDefault();
  spread(e.clipboardData.getData("text"), 0);   // fill from the first box
});

    7
    The complete event — fire once, when it is full
    
        
    Every mutation — typing, backspace, paste — routes through one afterChange() so there is a single place that asks "are we done?". Join the boxes and test for exactly LEN digits; only then call onComplete(code). Funnelling everything through one hook means the complete callback can never be missed (paste fills all six at once and still triggers it) and never double-fires per keystroke. This is the contract a real form cares about: give me the finished code, once.
    
        
    function afterChange(){
  const c = code();
  render();                                  // update styles + read-out
  if (/^\d{6}$/.test(c)) onComplete(c);      // FULL -> fire once
}
function onComplete(c){ /* validate, submit, show result (step 8) */ }

    8
    Validate + show the result
    
        
    On complete you would normally POST the code to the server; in the demo we compare it to the one that was "sent". A match locks the field, paints every box green and shows verified ✓; a mismatch paints them red, shakes the row (a CSS keyframe toggled by a class), and clears the digits so the user can retry — with the message announced for screen readers. Keep the outcome as state (a class on the boxes) so the CSS does the visuals and the JS stays about logic.
    
        
    function onComplete(c){
  if (c === SENT){                       // server call in real life
    boxes.forEach(b => b.classList.add("done"));
    setStatus("ok", "verified ✓");
  } else {
    boxes.forEach(b => b.classList.add("err"));
    otp.classList.add("shake");
    setStatus("bad", "Incorrect code — try again");
    setTimeout(clearAll, 700);           // reset for another attempt
  }
}

    9
    The resend countdown
    
        
    Codes expire, so every OTP screen has a "Resend" that you cannot spam. Model it as a plain setInterval that ticks a remaining counter down each second while the button is disabled and labelled "Resend in 30s"; at zero, clear the interval and re-enable it. Clicking resend "sends" a fresh code, clears the boxes, refocuses the first, and restarts the timer. Always clearInterval before starting a new one so repeated clicks can never stack two timers.
    
        
    let timer = null, remaining = 0;
function startTimer(s){
  clearInterval(timer);
  remaining = s; resend.disabled = true;
  const tick = () => resend.textContent = "Resend in " + remaining + "s";
  tick();
  timer = setInterval(() => {
    if (--remaining <= 0){ clearInterval(timer); resend.disabled = false;
                           resend.textContent = "Resend code"; }
    else tick();
  }, 1000);
}

    ARIA + accessibility — the honest finish
    
        
    The boxes look like one field, so tell assistive tech that too. Wrap them in a role="group" with an aria-label ("verification code, 6 digits"), give each input its own aria-label="Digit N of 6", and pipe every meaningful change through one visually-hidden aria-live region so a screen-reader user hears "digit 3 entered" and "code complete, verified". autocomplete="one-time-code" lets phones surface the SMS code directly. None of this changes how it looks — it is the difference between a widget that demos and one you can ship.
    
        
    <div class="otp" role="group" aria-label="Verification code, 6 digits">
  <input aria-label="Digit 1 of 6" autocomplete="one-time-code" …>
  …
</div>
<div id="live" class="sr-only" role="status" aria-live="polite"></div>

function announce(msg){ live.textContent = msg; }   // one live region
// afterChange() -> announce("Digit " + n + " of 6"); onComplete -> announce("Verified")
