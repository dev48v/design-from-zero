DESIGNFROMZERO · DAY 64

⌘ Slash-command menu — the component that looks like a dropdown and is really a parser attached to a caret. Typing / does not open a menu; it opens a menu only at a word boundary, and the menu stays open only while the text after the slash is still a plausible query — so 3/4 and a URL never trigger it, and typing a space usually closes it. Filtering is subsequence matching with a real score (prefix beats word-start beats scattered), not includes(), and the page shows the score for every candidate so you can see why the order is what it is. Keyboard handling is the part everyone gets wrong: arrows must not move the caret while the menu is open, Enter must not insert a newline, Escape must close the menu without losing focus, and the whole thing must be announced to a screen reader as a combobox with aria-activedescendant — because a menu you can only use with a mouse is not a command palette. The matcher is fuzz-tested in Node against a brute-force subsequence checker.

Type / to open the menu, then keep typing to filter. ↑ ↓ to move, Enter or Tab to insert, Esc to close. Then try the cases that should not open it: 3/4, and/or, https://x.com.

It is not a dropdown. It is a parser with a caret.


      
The naive implementation is one line: when the user types /, show the menu. It
      works in the demo and is wrong the moment somebody types a fraction, a date, a file path or a
      URL. Three quarters becomes a command palette.


      
The trigger is a boundary condition

      
A slash starts a command only if it is at the start of a line or preceded by
      whitespace. That single condition removes every false positive above:


      

        
"/"          → opens      (start of line)
"text /"     → opens      (preceded by a space)
"3/4"        → no         (preceded by a digit)
"and/or"     → no         (preceded by a letter)
"https://x"  → no         (preceded by ':' then '/')

      


      
Derive the state, do not store it

      
The tempting design is a boolean menuOpen that you set on / and
      clear on various events. It will drift — the user pastes, undoes, clicks elsewhere, deletes the
      slash from the middle of the query — and now the menu is open with nothing to filter on.

      
Instead, compute it from the text before the caret every time anything changes:

      
{ open: boolean, query: string, slashAt: number } = parseTrigger(textBeforeCaret)

      
Delete the slash and the menu closes because parseTrigger stops finding one, not
      because some handler remembered to close it.


      
Filtering: subsequence, with a score

      
includes() is too strict — nobody types headi to reach
      "Heading 1", they type h1. Plain subsequence matching is too loose: it ranks
      "Bulleted list" above "Heading 1" for the query h1 because it found an
      h and a 1 somewhere.

      
So the matcher returns a score, and the score is made of things that correspond to what
      people actually mean:

      
    
        
  • prefix — the query starts the candidate
    • 
        
  • word start — each matched character begins a word ("h1" → Heading 1)
    • 
        
  • adjacency — consecutive matches beat scattered ones
    • 
        
  • penalties — for gaps, and for a very long candidate
    • 
      

      
The panel on the TRY IT tab prints the score for every candidate, so the ranking is
      inspectable rather than mysterious.


      
The keyboard is the whole feature

      

        
Every arrow key that moves the caret while the menu is open is a bug.
        Every Enter that inserts a newline instead of running the command is a bug. Both require
        preventDefault(), and both are invisible in a mouse-driven demo — which is why
        so many slash menus feel broken the first time you try to use them without touching the
        mouse.

      


      
Escape must not steal focus

      
Closing on Escape is easy. Closing on Escape while leaving the caret exactly where it
      was is the part that matters — otherwise the user is punished for changing their mind.


      
Accessibility is not decoration here

      
The editor is the combobox; the menu is the listbox; the highlighted
      row is pointed at by aria-activedescendant. Focus never leaves the editor, which is
      exactly why the ARIA pattern exists — a screen reader needs to be told which row is current
      even though focus has not moved.

      
Announcing "0 results" matters too. Silence is indistinguishable from a broken menu.


      
Closing rules, stated

      
Close on: Escape, a space that produces no matches, deleting the slash, clicking outside, or
      running a command. Do not close on every space — multi-word commands like
      /code block need one, which is why the rule is "no matches" rather than "any
      whitespace".


    

  






  

    


      
🔨 Build it yourself


      
1. Parse the trigger from the text before the caret

      
function parseTrigger(before, maxQuery = 24){
  const slash = before.lastIndexOf("/");
  if (slash === -1) return { open:false, query:"", slashAt:-1 };

  // boundary: start of line, or preceded by whitespace
  const prev = slash === 0 ? "\n" : before[slash - 1];
  if (!/\s/.test(prev)) return { open:false, query:"", slashAt:-1 };

  const query = before.slice(slash + 1);
  if (query.length > maxQuery) return { open:false, query:"", slashAt:-1 };
  if (/\n/.test(query))        return { open:false, query:"", slashAt:-1 };
  return { open:true, query, slashAt:slash };
}

      
Pure, synchronous, and testable without a DOM. Everything else reads from it.


      
2. Score a candidate

      
function score(query, label){
  if (!query) return { hit:true, score:1, positions:[] };
  const q = query.toLowerCase(), s = label.toLowerCase();
  let qi = 0, prev = -2, total = 0;
  const positions = [];
  for (let i = 0; i < s.length && qi < q.length; i++){
    if (s[i] !== q[qi]) continue;
    let point = 1;
    if (i === 0) point += 8;                                  // prefix
    else if (/[\s\-_]/.test(s[i-1])) point += 5;              // word start
    if (i === prev + 1) point += 3;                           // adjacency
    else if (prev >= 0) point -= Math.min(3, i - prev - 1);   // gap penalty
    total += point; positions.push(i); prev = i; qi++;
  }
  if (qi < q.length) return { hit:false, score:0, positions:[] };
  return { hit:true, score: total - label.length * 0.05, positions };
}


      
3. Check it against the plain definition

      
The scorer is fiddly, so pin its yes/no answer to something obviously correct:

      
const isSubsequence = (q, s) => {
  let i = 0;
  for (const ch of s.toLowerCase()) if (ch === q[i]) i++;
  return i === q.length;
};
// for random q and s: score(q,s).hit  ===  isSubsequence(q, s)

      
Five thousand random pairs. Any disagreement means the scorer is rejecting things it should
      match or matching things it should not, and the ranking is the least of your problems.


      
4. Own the keys before the editor sees them

      
ed.addEventListener("keydown", e => {
  const t = trigger();                       // derived, not stored
  if (!t.open) return;                       // menu closed: hands off entirely
  switch (e.key){
    case "ArrowDown": e.preventDefault(); move(+1); break;
    case "ArrowUp":   e.preventDefault(); move(-1); break;
    case "Enter":
    case "Tab":       if (matches.length){ e.preventDefault(); run(matches[sel]); } break;
    case "Escape":    e.preventDefault(); dismiss(); break;   // caret stays put
  }
});

      
The early return matters as much as the cases. A handler that swallows arrows
      when the menu is closed breaks ordinary text editing, and it is a maddening bug to find.


      
5. Replace the query, not the whole line

      
function run(cmd){
  const before = textBeforeCaret();
  const t = parseTrigger(before);
  // delete exactly from the slash to the caret - never more
  deleteRange(t.slashAt, before.length);
  insert(cmd.insert);
}


      
6. Wire the ARIA, and mean it

      
ed.setAttribute("role", "combobox");
ed.setAttribute("aria-expanded", String(open));
ed.setAttribute("aria-controls", "menu");
ed.setAttribute("aria-activedescendant", open ? ("cmd-" + sel) : "");
menu.setAttribute("role", "listbox");
item.setAttribute("role", "option");
item.setAttribute("aria-selected", String(i === sel));

      
Focus stays in the editor throughout. aria-activedescendant is precisely the
      mechanism for "the focused element is here, but the interesting row is over there".
