Apple Settings — the inset-grouped list that organises every option on iOS and macOS into rounded cards of rows, each card introduced by an uppercase header and closed by a small grey footnote. Every row is a leading icon tile + label + a trailing accessory, and the accessory is the whole vocabulary of the pattern: an animated iOS toggle switch (role="switch", sliding knob), a chevron that shows the current value and pushes a subpage onto an in-panel navigation stack — a horizontal strip of screens translated by depth, with a ‹ Back button that names where you came from — a checkmark selection row inside a radiogroup, and a slider. State is real: flip Dark and the entire panel repaints from its own tokens, drag Text Size and every label grows, pick a network or wallpaper deep in a subpage and the value flows back to the row that pushed it. Vanilla HTML, CSS and JS — no libraries, the model drives every pixel.

The grouped list — tiles, switches, chevrons that push, and checkmarks that flow back.

A settings screen is not one long list — it is inset groups of rounded cards, each a cluster of related rows under an uppercase header and above a grey footnote. Try the live phone: flip a switch (watch the knob slide), tap a row with a chevron to push a subpage — the whole screen slides left and a ‹ Back button appears named after the screen you left. Inside Display & Brightness choose Dark and the panel repaints itself; drag Text Size and every label grows; inside Wi-Fi or Wallpaper tap an option to move the checkmark — then go back and see the value waiting on the row that sent you. Every switch, slider and checkmark writes to one state object. This preview only reads it — which is why it can never drift from the list.

iOS Settings, macOS System Settings, the settings pane of a hundred apps — the same shape each time: inset groups of rows, a tile to scan by, a trailing accessory that tells you what a row does, and a push stack that trades depth for a flat, uncluttered screen. Keep it honest — a switch for an instant on/off, a chevron when there is more behind it, a checkmark for one-of-many, real focusable controls, role="switch"/radiogroup and a back that says where it returns. Get those and a screen with fifty options still feels like nothing to navigate.

🔨 Build it yourself

    
A settings screen is a model rendered into inset groups, plus a navigation stack. We start from the anatomy — group = header + rounded card of rows + footnote — describe the whole screen as data, render a row as tile + label + accessory, build the four accessories (switch, chevron, checkmark, slider), hold all values in one state object, wire the push/pop stack as a translated strip, make the navbar name the screen you left, let a deep selection flow back to its parent row, and finish with the a11y. Vanilla HTML, CSS and JS — no framework, no dependencies.

    
    
      
  1. 
        
    1
    The anatomy — header, card, footnote
    
        
    The inset-grouped list is three parts per group: an uppercase header, a rounded card that clips its rows, and a small grey footnote. The card’s overflow:hidden is what rounds the first and last rows for free; the hairline separators are inset to start after the icon tile, never under it.
    
        
    .s-group  { margin:0 16px 22px; }         /* inset from the edges */
.s-header { text-transform:uppercase; color:#6d6d72; }
.s-card   { background:#fff; border-radius:12px; overflow:hidden; }
.s-footer { color:#6d6d72; font-size:12px; }

/* separator inset so it lines up with the label, not the tile */
.s-row:not(:last-child)::after { left:57px; height:.5px; background:#d7d7db; }

    2
    The whole screen is data
    
        
    Do not hand-write rows. Describe every screen as a model: a map of screens, each a list of groups, each group a list of row descriptors. A descriptor names its type, its icon and tint, the state key it reads/writes, and (for a chevron row) the screen it pushes and a value function. One data structure, one renderer.
    
        
    const SCREENS = {
  root: { title:"Settings", groups:[
    { footer:"Airplane Mode turns off Wi-Fi & Bluetooth.", rows:[
      { type:"toggle", key:"airplane", label:"Airplane Mode", icon:"airplane", tint:"#ff9500" },
      { type:"nav", label:"Wi-Fi", icon:"wifi", tint:"#007aff",
        screen:"wifi", value: s => s.wifiOn ? s.network : "Off" },
    ]},
    { header:"PREFERENCES", rows:[ /* … */ ] },
  ]},
  display: { title:"Display & Brightness", groups:[ /* … */ ] },
};

    3
    A row = tile + label + accessory
    
        
    Every row shares a skeleton: a coloured tile (29×29, a white SVG inside), a flexible label, and a trailing slot for the accessory. Build cells with textContent, never string concatenation, so a label can never smuggle in markup. The tile’s SVG is trusted static icon markup.
    
        
    function tile(name, tint){
  const t = document.createElement("div");
  t.className = "s-tile"; t.style.background = tint;
  t.innerHTML = ICON[name];          // trusted static SVG
  return t;
}
// row shell: <div class="s-row"> [tile] <div class="s-label"> <div class="s-trail">
label.textContent = r.label;         // safe: never innerHTML for data

    4
    Accessory 1 — the switch
    
        
    The toggle is a real <button> with role="switch" and aria-checked. The knob is a circle moved with a CSS transform transition — the class .on both colours the track and slides the knob, so the visual and the announced state are set from one boolean and can never disagree.
    
        
    const sw = document.createElement("button");
sw.type = "button"; sw.setAttribute("role", "switch");
sw.className = "s-switch" + (state[r.key] ? " on" : "");
sw.setAttribute("aria-checked", String(!!state[r.key]));
sw.innerHTML = '<span class="s-knob"></span>';
sw.onclick = () => {
  state[r.key] = !state[r.key];                 // flip the source of truth
  sw.classList.toggle("on", state[r.key]);      // .on slides the knob (CSS)
  sw.setAttribute("aria-checked", String(state[r.key]));
  onStateChange();                              // repaint everything that reads it
};

  5. 
        
    5
    Accessory 2 — the chevron that pushes
    
        
    A nav row is a button showing the current value and a › chevron. Its value is a function of state, so it always shows the truth; we stash that function on the element so it can be recomputed in place when the value changes deep in a subpage. Clicking it pushes the target screen.
    
        
    const v = document.createElement("span");
v.className = "s-value nav-val";
v.textContent = r.value(state);       // "HomeNet 5G", "Dark", …
v._valueFn = r.value;                 // remember how to recompute it
row.onclick = () => push(r.screen);   // slide the subpage in

// later, when any state changes:
function updateNavValues(){
  document.querySelectorAll(".nav-val")
    .forEach(el => { if (el._valueFn) el.textContent = el._valueFn(state); });
}

    6
    Accessory 3 & 4 — checkmark & slider
    
        
    A selection group is a radiogroup of rows; the chosen one gets aria-checked and a blue checkmark. Selecting moves the mark to the tapped row (remove .show from siblings, add to this one) — no re-render needed. A slider row is a native <input type=range> writing straight to state on every input.
    
        
    row.setAttribute("role", "radio");
row.setAttribute("aria-checked", String(state[r.key] === r.value));
row.onclick = () => {
  state[r.key] = r.value;
  card.querySelectorAll(".s-check").forEach(c => c.classList.remove("show"));
  check.classList.add("show");        // checkmark animates to here
  onStateChange();
};

// slider
input.oninput = () => { state[r.key] = +input.value; onStateChange(); };

    7
    The navigation stack — push & pop
    
        
    Navigation is an array of screen ids. The DOM is a strip of full-width panels laid side by side; you show depth d by translating the strip -d×100%. Push builds a fresh panel, appends it, then shifts the strip — it slides in. Pop shifts back, then removes the panel after the transition.
    
        
    let nav = ["root"];
function push(id){
  nav.push(id);
  stack.append(renderScreen(id));                 // fresh panel off to the right
  stack.style.transform = `translateX(-${(nav.length-1)*100}%)`;
  syncNavbar();
}
function pop(){
  if (nav.length <= 1) return;
  nav.pop();
  stack.style.transform = `translateX(-${(nav.length-1)*100}%)`;
  stack.addEventListener("transitionend", function h(){
    stack.lastElementChild.remove();              // drop it once off-screen
    stack.removeEventListener("transitionend", h);
  });
  syncNavbar();
}

  8. 
        
    8
    The navbar names where you came from
    
        
    The bar reads from the stack: the centre title is the top screen, and the Back button is labelled with the previous screen’s title — that is the small touch that makes an iOS back button feel oriented. At the root there is nothing to return to, so the button hides.
    
        
    function syncNavbar(){
  const top  = nav[nav.length - 1];
  const prev = nav[nav.length - 2];
  title.textContent = SCREENS[top].title;
  if (prev){
    back.classList.add("show");
    backLabel.textContent = SCREENS[prev].title;    // "‹ Settings"
    back.setAttribute("aria-label", "Back to " + SCREENS[prev].title);
  } else {
    back.classList.remove("show");                  // root: nothing behind
  }
}

    9
    One state object, one repaint
    
        
    Every control writes to a single state. After a write, onStateChange() fans out: recolour the panel for Dark, scale labels for Text Size, dim for Brightness, recompute the nav values (so a deep pick flows back), and repaint the preview. The list reacts to its own state — that is what makes it feel alive rather than static.
    
        
    function onStateChange(){
  frame.classList.toggle("dark", state.appearance === "dark");   // repaint tokens
  frame.style.setProperty("--s-scale", 0.82 + state.textSize*0.06); // grow labels
  dim.style.opacity = (100 - state.brightness) / 100 * 0.45;        // brightness
  updateNavValues();     // Wi-Fi row now reads the network you just picked
  paintPreview();        // the read-out card
}

    A11y & when to use which accessory
    
        
    Real <button>s give Tab/Enter/Space for free; add Esc to pop the stack. Mark switches role="switch"+aria-checked, wrap selection groups in role="radiogroup" with aria-checked radios, and keep the chevron/checkmark decorative (aria-hidden). Choose the accessory by meaning: switch = instant on/off, chevron = there is more behind it, checkmark = one of many, slider = a continuous range.
    
        
    frame.addEventListener("keydown", e => {
  if (e.key === "Escape") pop();          // back
});
// switch      -> role="switch"  aria-checked   (instant on/off)
// nav+chevron -> a real button, value is a fn  (drills deeper)
// select      -> role="radio" in a radiogroup  (one of many)
// slider      -> <input type=range>             (continuous)
