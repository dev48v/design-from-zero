DesignFromZero · Day 57

iOS Toggle Switch — the sliding on/off control, built as a real <input type=checkbox> in disguise. The checkbox is visually hidden but fully present — still focusable, still Space-togglable, still the single source of :checked — and a <span> track + round thumb are layered over it. The whole animation is two CSS rules: input:checked ~ .sw-track swaps the rail colour and ~ .sw-track .sw-thumb slides the knob one translateX(width−height) on a spring-y overshoot bezier, so a pure-CSS switch works with zero JavaScript. Adding role="switch" makes assistive tech announce “on / off” instead of “checked”, and JS only ever mirrors aria-checked and feeds a live state panel. A gallery shows the iOS green, a Material thin-track overshoot thumb, sm / md / lg sizes and colour themes (all just CSS custom properties), plus disabled and loading states and a settings-row usage where the whole row is one label. Finally a JS drag-to-toggle variant uses pointer capture to let you fling the thumb — it kills the transition mid-drag, then commits past the 50% mark and hands motion back to CSS for the settle. No libraries, no placeholders.

Every settings screen, feature flag and dark-mode switch is this same shape: a hidden native checkbox for behaviour, a track + thumb for looks, one :checked selector that slides the knob with a spring, and role="switch" so it announces on / off. 🔨 Build it yourself

    
A toggle switch is a native checkbox in disguise. We start from the markup (label + input + track + thumb), hide the input without removing it, style the track and thumb, do the whole reveal in one :checked selector, add a focus ring and a spring transition, spin up variants (sizes, themes, Material) from CSS custom properties, handle disabled and loading, wire a live state panel that mirrors aria-checked, and finish with a JS drag-to-toggle. Vanilla HTML, CSS and JS — no framework, no dependencies.

    
    
      
  1. 
        
    1
    The markup: a real checkbox inside a label
    
        
    A <label> wraps a <input type="checkbox"> plus two spans — the track and, inside it, the thumb. Because the input lives inside the label, clicking anywhere on the switch toggles it, and the label is the click / tap target for free. role="switch" tells assistive tech to say “on / off” rather than “checked”.
    
        
    <label class="sw">
  <input type="checkbox" role="switch" aria-label="Wi-Fi">
  <span class="sw-track">
    <span class="sw-thumb"></span>
  </span>
</label>
    
      
    2. 
      
  2. 
        
    2
    Hide the input — but keep it real
    
        
    Do not use display:none or visibility:hidden — that would kill focus and the keyboard. Instead lay the input over the whole switch at opacity:0. It is invisible, yet still focusable, still clickable, still Space-togglable, and still the element that owns :checked. Give it the top z-index so it catches the clicks; the track and thumb are pointer-events:none.
    
        
    .sw          { position:relative; display:inline-flex; width:52px; height:32px; cursor:pointer; }
.sw > input  { position:absolute; inset:0; width:100%; height:100%;
               margin:0; opacity:0; cursor:inherit; z-index:2; }  /* invisible, not gone */
.sw-track, .sw-thumb { pointer-events:none; }
    
      
    3. 
      
  3. 
        
    3
    Style the track & thumb
    
        
    The track is a pill (border-radius:999px) filling the switch. The thumb is a circle inset by --pad on every side, so its diameter is height − 2×pad. A soft shadow lifts it off the rail. Everything is expressed against three custom properties — --w, --h, --pad — which is what makes sizing trivial later.
    
        
    .sw { --w:52px; --h:32px; --pad:3px; --track-off:#e5e7eb; --track-on:#34c759; }

.sw-track { position:absolute; inset:0; border-radius:999px; background:var(--track-off); }
.sw-thumb { position:absolute; top:var(--pad); left:var(--pad);
            width:calc(var(--h) - var(--pad)*2); height:calc(var(--h) - var(--pad)*2);
            border-radius:50%; background:#fff;
            box-shadow:0 1px 2px rgba(15,23,42,.28), 0 3px 8px rgba(15,23,42,.14); }
    
      
    4. 
      
  4. 
        
    4
    The reveal is one :checked selector
    
        
    Here is the entire behaviour. When the hidden input is checked, the sibling combinator ~ repaints the track and slides the thumb. The travel distance is exactly width − height: the thumb starts pad from the left and must end pad from the right, and the two pads cancel. No JavaScript touches this — a pure-CSS switch is fully working right here.
    
        
    .sw > input:checked ~ .sw-track           { background:var(--track-on); }
.sw > input:checked ~ .sw-track .sw-thumb { transform:translateX(calc(var(--w) - var(--h))); }

/* 52 - 32 = 20px of travel. start:pad(3) end:52-3-26 => 23, delta = 20. */
    
      
    5. 
      
  5. 
        
    5
    Focus ring on the track
    
        
    Because the real control is invisible, its focus outline would be invisible too. Catch :focus-visible on the input and paint a ring on the track instead. :focus-visible (not :focus) means the ring shows for keyboard users but not on a mouse click — the modern default.
    
        
    .sw > input:focus-visible ~ .sw-track {
  box-shadow:0 0 0 4px rgba(99,102,241,.45);
}
    
      
    6. 
      
  6. 
        
    6
    The spring — an overshoot bezier
    
        
    A linear slide feels mechanical. Transition the thumb's transform with a cubic-bezier whose second control point pokes above 1 — the curve overshoots the target and eases back, so the knob lands with a tiny bounce. Only transform and background animate; both are compositor-friendly, so it stays 60fps.
    
        
    .sw-thumb { transition:transform .42s cubic-bezier(.34, 1.56, .64, 1); }  /* 1.56 > 1 = overshoot */
.sw-track { transition:background .42s ease; }

/* Material wants more punch: */
.sw-material { --ease:cubic-bezier(.2, 1.75, .3, 1); }
    
      
    7. 
      
  7. 
        
    7
    Variants from custom properties
    
        
    Because every dimension and colour is a variable, a variant is just a class that re-sets a few of them — the base rules and the travel math are untouched. Sizes swap --w --h --pad; themes repoint --track-on; Material thins the track and grows the thumb so it overshoots the rail.
    
        
    .sw.sw-sm { --w:40px; --h:24px; --pad:2px; }
.sw.sw-lg { --w:66px; --h:40px; --pad:4px; }

.sw.t-indigo { --track-on:#6366f1; }
.sw.t-rose   { --track-on:#f43f5e; }

.sw.sw-material { --w:46px; --h:20px; height:28px; }          /* box taller than the thin track */
.sw.sw-material .sw-track { top:7px; bottom:7px; }            /* 14px rail, centred */
.sw.sw-material .sw-thumb { top:50%; margin-top:-10px; width:20px; height:20px; }  /* overshoots */
    
      
    8. 
      
  8. 
        
    8
    Disabled & loading
    
        
    A disabled native checkbox already refuses clicks, keyboard and focus — we only need to look disabled: dim the switch and change the cursor, keyed off :has(> input:disabled). Loading is a spinner drawn as a ::after ring inside the thumb; pair it with aria-busy="true" and a disabled input so the value can't change mid-flight.
    
        
    .sw:has(> input:disabled) { cursor:not-allowed; opacity:.45; }

.sw.sw-loading .sw-thumb::after {
  content:""; position:absolute; inset:22%; border-radius:50%;
  border:2px solid rgba(15,23,42,.22); border-top-color:var(--track-on);
  animation:sw-spin .7s linear infinite;
}
@keyframes sw-spin { to { transform:rotate(360deg); } }
    
      
    9. 
      
  9. 
        
    9
    Mirror aria-checked + a live panel
    
        
    The CSS switch already works; JS is optional polish. On every change we copy input.checked into aria-checked (belt-and-braces for a role="switch") and repaint a read-out. Because the checkbox is the single source of truth, click, drag and keyboard all flow through the same change event — the panel can never drift from the switch.
    
        
    document.querySelectorAll('.sw > input').forEach(inp => {
  const sync = () => inp.setAttribute('aria-checked', inp.checked ? 'true' : 'false');
  sync();                              // reflect the initial state
  inp.addEventListener('change', () => { sync(); paintPanel(inp); });
});

  10. 
        
    10
    JS drag-to-toggle
    
        
    To let users fling the thumb, capture the pointer on pointerdown, add a .dragging class that kills the transition (so the thumb tracks the finger 1:1), and set an inline translateX clamped to the track. On release, drop the class to re-enable the spring, decide the final state by whether you passed the halfway mark, write it back to input.checked, then clear the inline transform so CSS animates the settle. If the pointer actually moved, cancel the click that would otherwise double-toggle.
    
        
    sw.addEventListener('pointerdown', e => {
  if (input.disabled) return;
  maxX = sw.clientWidth - thumb.offsetWidth - thumb.offsetLeft * 2;  // = width - height
  startX = e.clientX; startPos = input.checked ? maxX : 0; moved = false;
  sw.classList.add('dragging'); sw.setPointerCapture(e.pointerId);
});
sw.addEventListener('pointermove', e => {
  if (!dragging) return;
  const d = e.clientX - startX; if (Math.abs(d) > 3) moved = true;
  cur = Math.min(maxX, Math.max(0, startPos + d));
  thumb.style.transform = `translateX(${cur}px)`;
});
function end(e){
  sw.classList.remove('dragging');          // spring is back
  if (moved){
    const final = cur > maxX / 2;           // committed past halfway?
    void thumb.offsetWidth;                 // flush: transition on, thumb still at `cur`
    input.checked = final;                  // flip the native boolean
    input.dispatchEvent(new Event('change', { bubbles:true }));
    thumb.style.transform = '';             // hand back to CSS -> it animates the settle
    suppressClick = true;                   // a drag must not also fire a toggle-click
  } else { thumb.style.transform = ''; }    // a tap -> let the native click toggle
}
input.addEventListener('click', e => { if (suppressClick){ e.preventDefault(); suppressClick = false; } });
