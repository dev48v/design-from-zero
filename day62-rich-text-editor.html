DesignFromZero · Day 62

Rich text editor — a WYSIWYG contenteditable whose source of truth is a document model, never the DOM. The whole document is { text, marks }: one plain string plus a flat list of half-open intervals {from, to, type} for bold, italic, code, strike and link. Every keystroke is intercepted at beforeinput, applied to that model, re-rendered, and the caret is put back — so the browser never gets to invent markup. toggleMark has real semantics: if every character in the range already carries the mark it is removed, otherwise it is added — the behaviour every editor has and almost nobody gets right first try. Marks are kept canonical by a normaliser that sorts, merges adjacent and overlapping same-type intervals and drops empty ones, and the page shows the raw list beside the normalised one. Positions are mapped, not rebuilt: one mapPos function moves every endpoint through an insert or a delete under a stated left-exclusive, right-inclusive boundary rule, so typing at the right edge of bold extends it, typing at the left edge does not, a delete across a mark clips it and a delete that swallows one erases it. Because intervals overlap you cannot wrap each one in its own tag, so a boundary sweep flattens them into non-overlapping style runs that are emitted as correctly nested inline elements in a fixed order. Selection is bridged both ways by walking text nodes and <br>s, which is exactly where naive editors lose the caret. Plus undo with coalescing (consecutive characters collapse into one entry, a mark change or a caret jump breaks the run), paste sanitisation through an allowlist that converts b/strong/i/em/code/s/a into marks and counts what it threw away, and markdown input rules that rewrite **x**, _x_, ~~x~~ and backticks into marks as you type. The pure core is fuzz-tested against a completely different representation — one Set per character — in a Node script. No libraries, no images.

The model is the document. The DOM is just a picture of it.

Type anywhere and watch the mark intervals move in the panel on the right — type at the right edge of a bold run and it grows, type at the left edge and it does not. Select a range and press Ctrl+B: if every character already carries bold it is removed, otherwise it is added — select a half-bold range twice to see both branches. Delete across a mark and watch it get clipped; delete a whole mark and watch it vanish from the list. Type **like this** or a backtick pair and the markdown rule rewrites it into a mark and eats the source characters. Hit the paste button to run a hostile Word-style HTML blob through the allowlist and read exactly how many nodes and attributes were rejected. Then Ctrl+Z — a whole typed word undoes as one step because consecutive insertions coalesce.

A real editor — type in it, select in it, paste into it, undo it. Every number on this page was computed by the code running beside it.

🔨 Build it yourself

    
A rich text editor is not a styled contenteditable. It is a document model with a renderer bolted to the front and an input interceptor bolted to the back. Get the order right and everything downstream — undo, collaboration, paste, markdown shortcuts, serialisation — becomes a small pure function over { text, marks }. Get it wrong and you spend the rest of the project fighting the browser for control of markup you did not write. Everything below is vanilla HTML, CSS and JavaScript: no editor framework, no schema library, no execCommand.

    
    

      
  1. 
        
    1
    Define the document, and make it boring
    
        
    The document is a plain string plus a flat list of half-open intervals. Half-open (from inclusive, to exclusive) is not a style choice: it makes length to - from, makes two ranges adjacent when a.to === b.from, and makes a zero-length range an obvious from === to rather than something you have to reason about. Every mark carries only a type; a link additionally carries an href. Nothing else — no node ids, no parent pointers, no DOM references. If a piece of state cannot survive being JSON.stringify'd and read back, it does not belong in the model.
    
        
    // the entire document
const doc = {
  text: "The document model is the truth.",
  marks: [
    { from: 4,  to: 18, type: "bold" },
    { from: 12, to: 31, type: "italic" },
    { from: 0,  to: 3,  type: "link", href: "https://example.com" }
  ]
};

// half-open: length is to - from, adjacency is a.to === b.from,
// and an empty range is exactly from === to.
const MARK_ORDER = ["link", "bold", "italic", "strike", "code"];
const markKey = m => m.type === "link" ? "link\u0000" + (m.href || "") : m.type;
    
        
    The markKey detail earns its keep immediately: two bold intervals that touch are the same mark and must merge, but two links that touch with different hrefs are not and must not. Keying on type-plus-attributes lets one normaliser handle both without a special case.
    
      
    2. 

      
  2. 
        
    2
    Normalise, so there is one representation of every document
    
        
    Without a canonical form the same visual document has infinitely many mark lists, and every comparison you ever write — is this dirty, did this change, do these two clients agree — becomes unreliable. So define one: clamp to the text, drop empties, sort, and merge anything of the same key that overlaps or touches. Run it at the end of every operation. It is around twenty lines and it retires an entire family of bugs, including the classic where bolding a word twice leaves two identical intervals stacked on each other and the next toggle only removes one.
    
        
    function normalizeMarks(marks, len){
  const buckets = new Map();
  for (const m of marks || []){
    if (!m || !m.type) continue;
    let f = Math.min(m.from, m.to), t = Math.max(m.from, m.to);   // from > to is fine
    f = Math.max(0, f); t = Math.max(0, t);
    if (typeof len === "number"){ f = Math.min(f, len); t = Math.min(t, len); }
    if (f >= t) continue;                                          // drop empties
    const k = markKey(m);
    if (!buckets.has(k)) buckets.set(k, []);
    buckets.get(k).push([f, t]);
  }
  const out = [];
  for (const [k, list] of buckets){
    list.sort((a, b) => a[0] - b[0] || a[1] - b[1]);
    let cf = list[0][0], ct = list[0][1];
    for (let i = 1; i < list.length; i++){
      if (list[i][0] <= ct) ct = Math.max(ct, list[i][1]);          // overlap OR touch
      else { out.push(mkMark(k, cf, ct)); cf = list[i][0]; ct = list[i][1]; }
    }
    out.push(mkMark(k, cf, ct));
  }
  return out.sort((a, b) => a.from - b.from || a.to - b.to
                          || orderOf(a.type) - orderOf(b.type));
}
    
      
    3. 

      
  3. 
        
    3
    Toggle means toggle: all-on removes, anything-off adds
    
        
    This is the function that separates an editor from a demo. Select a range where half the characters are bold and press the bold button: the correct behaviour is to make the whole range bold, and only a second press should clear it. That falls straight out of one predicate — does every character in the range already carry this type — which you answer with a coverage sweep rather than by checking whether any single interval contains the range, because the coverage may be spread across several adjacent intervals. Adding first strips same-type marks inside the range, which is what makes a link exclusive: a range can only point at one URL.
    
        
    function hasMarkThroughout(marks, from, to, type){
  const a = Math.min(from, to), b = Math.max(from, to);
  if (a >= b) return false;                     // a caret covers nothing
  const ivs = (marks || []).filter(m => m.type === type)
    .map(m => [Math.min(m.from, m.to), Math.max(m.from, m.to)])
    .filter(iv => iv[0] < iv[1]).sort((x, y) => x[0] - y[0]);
  let cursor = a;
  for (const iv of ivs){
    if (iv[0] > cursor) return false;            // a hole before this interval
    cursor = Math.max(cursor, iv[1]);
    if (cursor >= b) return true;
  }
  return cursor >= b;
}

function toggleMark(marks, from, to, type, attrs){
  const a = Math.min(from, to), b = Math.max(from, to);
  if (a >= b) return normalizeMarks(marks);      // nothing to do on a caret
  return hasMarkThroughout(marks, a, b, type)
    ? removeMark(marks, a, b, type)              // all on  -> clear
    : addMark(marks, a, b, type, attrs);         // any off -> fill
}
    
        
    removeMark is the mirror image and is where half-open pays off again: for every overlapping interval of that type, keep [m.from, a) if non-empty and [b, m.to) if non-empty, and let the normaliser throw away whatever collapsed.
    
      
    4. 

      
  4. 
        
    4
    One position-mapping function, and a boundary rule you can say out loud
    
        
    Do not rebuild marks after an edit — map them. Every endpoint of every mark is just a position, and a change moves positions in a way you can write in four lines. Then choose and state the boundary rule, because the ambiguous case is real: text inserted exactly at mark.to can go inside or outside. This editor is left-exclusive, right-inclusive — insert at from lands outside, insert at to lands inside — which is why continuing to type at the end of a bold word stays bold, and typing immediately before it does not. The elegant consequence is that both endpoints use the identical comparison, so mapping is one function and not two.
    
        
    // ch = { kind:"insert", at, len } | { kind:"delete", from, to }
function mapPos(pos, ch){
  if (ch.kind === "insert") return ch.at <= pos ? pos + ch.len : pos;
  const d = ch.to - ch.from;
  return pos <= ch.from ? pos
       : pos >= ch.to   ? pos - d
       : ch.from;                       // inside the deleted span -> collapse
}

const mapMarks = (marks, ch) => (marks || []).map(m => ({
  ...m, from: mapPos(Math.min(m.from, m.to), ch), to: mapPos(Math.max(m.from, m.to), ch)
}));

function applyInsert(text, marks, at, str){
  const p = Math.max(0, Math.min(text.length, at));
  const ch = { kind: "insert", at: p, len: String(str).length };
  const nt = text.slice(0, p) + str + text.slice(p);
  return { text: nt, marks: normalizeMarks(mapMarks(marks, ch), nt.length), change: ch };
}
    
        
    Delete falls out of the same mapPos: an endpoint before the deletion is untouched, one after it shifts left by the deleted length, and one inside collapses to the deletion point. A mark straddling the boundary is therefore clipped, and a mark entirely inside collapses to from === to and is dropped by the normaliser — erased with no special case anywhere.
    
      
    5. 

      
  5. 
        
    5
    Sweep overlapping intervals into non-overlapping style runs
    
        
    Here is the trap. Marks overlap freely — bold across words 1–3 and italic across words 2–4 is a perfectly ordinary document — but HTML elements must nest, so you cannot emit one tag per interval without producing <b>a<i>b</b>c</i>, which no parser will keep. The fix is a boundary sweep: collect every from and every to plus the two ends of the text, sort them, and walk the gaps. Inside a gap no mark can start or stop, so the active set is constant, and the output is a strip of runs that tiles [0, text.length) exactly — no gaps, no overlaps, which is precisely the invariant to assert in a test.
    
        
    function styleRuns(text, marks){
  const len = text.length;
  if (!len) return [];
  const ms = normalizeMarks(marks, len);
  const pts = new Set([0, len]);
  for (const m of ms){ pts.add(m.from); pts.add(m.to); }
  const b = [...pts].sort((x, y) => x - y);
  const runs = [];
  for (let i = 0; i < b.length - 1; i++){
    const from = b[i], to = b[i + 1];
    if (from >= to) continue;
    const active = ms.filter(m => m.from <= from && m.to >= to)
                     .sort((x, y) => orderOf(x.type) - orderOf(y.type));
    runs.push({ from, to, text: text.slice(from, to),
                types: active.map(m => m.type),
                href: (active.find(m => m.type === "link") || {}).href || null });
  }
  return runs;
}

  6. 
        
    6
    Render runs to nested elements — in a fixed order
    
        
    Rendering is now trivial and, crucially, deterministic. Sort each run's active types by a single global order — link outermost, then bold, italic, strike, and code innermost — and wrap from the inside out. A fixed order means two adjacent runs with the same marks produce the same nesting, which is what lets the browser merge them and what stops the caret jumping when the DOM is rebuilt. Escape the text yourself, keep the surface at white-space: pre-wrap so real spaces survive without &nbsp;, and emit a <br> for each newline plus one extra trailing sentinel when the text ends in a newline — otherwise the browser refuses to show that last empty line.
    
        
    function wrapRun(str, run){
  let inner = esc(str);
  for (let i = run.types.length - 1; i >= 0; i--){         // inside -> out
    const t = run.types[i];
    if (t === "bold")        inner = "<strong>" + inner + "</strong>";
    else if (t === "italic") inner = "<em>"     + inner + "</em>";
    else if (t === "code")   inner = "<code>"   + inner + "</code>";
    else if (t === "strike") inner = "<s>"      + inner + "</s>";
    else if (t === "link")   inner = '<a href="' + esc(run.href || "") + '">' + inner + "</a>";
  }
  return inner;
}

let html = "";
for (const r of styleRuns(text, marks)){
  r.text.split("\n").forEach((part, i) => {
    if (i) html += "<br>";
    if (part) html += wrapRun(part, r);
  });
}
if (/\n$/.test(text)) html += '<br data-bogus="1">';    // show the final empty line
editor.innerHTML = html;

  7. 
        
    7
    Bridge the Selection API to model offsets — both ways
    
        
    This is where naive editors lose the caret. A DOM selection is (node, offset) where node is whatever text node or element the browser felt like, and your model wants a single integer. Walk the editor in document order collecting text nodes and <br>s — a <br> counts as exactly one character, the newline it represents — and accumulate lengths until you reach the point. Going the other way, walk the same list until the offset falls inside a node. Do this after every re-render, because you just replaced the entire subtree the selection was pointing into. Skip the trailing sentinel <br> in the walk, or every offset past the last newline will be one too large.
    
        
    function walkNodes(root){                  // text nodes and <br>, in order
  const out = [];
  (function rec(n){
    for (const c of n.childNodes){
      if (c.nodeType === 3) out.push(c);
      else if (c.nodeType === 1){
        if (c.dataset && c.dataset.bogus) continue;    // the sentinel is not text
        if (c.tagName === "BR") out.push(c); else rec(c);
      }
    }
  })(root);
  return out;
}

function offsetToPoint(root, offset){
  let acc = 0;
  for (const n of walkNodes(root)){
    const L = n.nodeType === 3 ? n.nodeValue.length : 1;
    if (offset <= acc + L){
      if (n.nodeType === 3) return { node: n, off: offset - acc };
      const p = n.parentNode, i = [...p.childNodes].indexOf(n);
      return { node: p, off: offset - acc === 0 ? i : i + 1 };
    }
    acc += L;
  }
  return { node: root, off: root.childNodes.length };
}
    
        
    The reverse direction has one wrinkle: the browser can hand you a point anchored on an element, not a text node. Rather than special-casing that, compare a collapsed Range at the point against each walked node with compareBoundaryPoints — before it, after it, or inside it — and the element case answers itself.

    8
    Intercept beforeinput and own every edit
    
        
    Left alone, a contenteditable will happily invent <font> tags, nested spans and unbalanced markup you never asked for, and your model will be a lie within three keystrokes. beforeinput is the fix: it fires before the browser mutates anything, it names the operation in inputType, and it is cancellable. Cancel it, apply the equivalent change to the model, re-render, restore the caret. The list of input types is long but the handling collapses into four buckets, and the fallthrough is simply preventDefault — refusing an edit you have not implemented is infinitely better than letting the DOM drift out of sync.
    
        
    editor.addEventListener("beforeinput", (e) => {
  const sel = getSel() || S.sel;
  const t = e.inputType;
  e.preventDefault();                                   // the browser never edits
  if (t === "insertText")                       typeText(e.data || "", sel);
  else if (t === "insertParagraph" ||
           t === "insertLineBreak")             typeText("\n", sel);
  else if (t.startsWith("delete"))              doDelete(t, sel);
  else if (t === "historyUndo")                 undo();
  else if (t === "historyRedo")                 redo();
  else if (t === "formatBold")                  applyToggle("bold");
  else if (t === "formatItalic")                applyToggle("italic");
});

// a collapsed backspace must not cut a surrogate pair in half
function stepBack(text, p){
  const c = text.charCodeAt(p - 1);
  return (c >= 0xDC00 && c <= 0xDFFF && p >= 2) ? p - 2 : p - 1;
}

    9
    Undo that groups your typing, paste that cannot hurt you, markdown that disappears
    
        
    Because every change produces a complete new model, history is a stack of snapshots and undo is an assignment. The only interesting part is coalescing: an undo that removes one character at a time is unusable, so consecutive single-character insertions merge into one entry when the new one starts exactly where the previous one ended and arrives inside a short window. Notice what that condition gives you for free — move the caret and the positions no longer chain, so the run breaks; press bold and the entry kind changes, so the run breaks. No extra flags.
    
        
    function canCoalesce(prev, next, windowMs){
  if (!prev || !next) return false;
  if (prev.kind !== "insert" || next.kind !== "insert") return false;
  if (prev.ch === "\n" || next.ch === "\n") return false;
  if (next.at !== prev.at + prev.len) return false;      // caret jump breaks it
  return (next.time - prev.time) <= (windowMs == null ? 700 : windowMs);
}

// paste: an allowlist that converts tags to marks and counts the refusals
const ALLOWED_TAGS = { B:"bold", STRONG:"bold", I:"italic", EM:"italic",
                       CODE:"code", S:"strike", STRIKE:"strike", DEL:"strike", A:"link" };
const DROPPED_TAGS = new Set(["SCRIPT","STYLE","IMG","IFRAME","OBJECT","EMBED",
                              "SVG","VIDEO","AUDIO","META","LINK","NOSCRIPT"]);

function safeHref(h){
  const s = String(h == null ? "" : h).trim();
  if (/^(https?:|mailto:)/i.test(s)) return s;
  if (/^[a-z][a-z0-9+.-]*:/i.test(s)) return "";         // javascript: and friends
  return s;                                               // relative URLs are fine
}
    
        
    The sanitiser walks a plain tree of {tag, attrs, children} rather than live DOM nodes, which keeps it pure and testable: allowed tags open a mark and record the spans their text occupies, dropped tags take their whole subtree with them, and everything else is unwrapped — its text survives, its identity does not. Markdown input rules are the same shape in reverse: after each inserted character, test a few anchored patterns against the text ending at the caret, and if one matches, splice the inner text back in with a mark and move the caret to the end of it.

    10
    Prove it against a different representation
    
        
    Interval arithmetic is exactly the kind of code that looks right and is wrong at the boundaries, so test it against an implementation that shares none of its shape. Represent the same document as one Set of active mark keys per character — hopelessly inefficient, trivially obviously correct — implement toggle, insert and delete over that array, and assert that expanding the interval engine's output back to per-character sets gives the identical answer. The boundary rule expressed in that language is beautifully simple: inserted characters inherit the set of the character to their left, which is the same rule as left-exclusive, right-inclusive, said differently. Then fuzz it: thousands of random documents, random operation sequences, and every adversarial case you can name.
    
        
    // ground truth: sets[i] = the mark keys active on character i
const expand = (len, marks) => {
  const s = Array.from({ length: len }, () => new Set());
  for (const m of marks) for (let i = m.from; i < m.to; i++) s[i].add(key(m));
  return s;
};

function gtInsert(sets, at, len){                  // independent of intervals
  const inherit = at > 0 ? new Set(sets[at - 1]) : new Set();
  const add = Array.from({ length: len }, () => new Set(inherit));
  return sets.slice(0, at).concat(add, sets.slice(at));
}

// then, for every random step:
assertSameSets(expand(r.text.length, r.marks), gtInsert(sets, at, str.length));
    
        
    The run sweep gets its own invariant, and it is the strongest one on the page: the runs must tile [0, text.length) — first starts at 0, each starts where the last ended, the last ends at the length — and every character inside a run must have exactly that run's style set. If that holds for a million random characters, the renderer cannot produce a hole or a double-styled character.

✅ Day 62 of DesignFromZero done — Rich text editor.
You built an editor whose truth is { text, marks } and whose contenteditable is only a projection. Toggle became a real predicate — all-on removes, anything-off adds — answered by a coverage sweep rather than by hoping one interval contains the range. Normalisation gave every document exactly one representation. One mapPos moved every endpoint through every change under a boundary rule you can say out loud, so extending, clipping and erasing marks needed no special cases. The boundary sweep turned overlapping intervals into runs that tile the text, which is the only way to get valid nesting out of marks that legally cross. And the Selection bridge kept the caret alive across a full re-render. 👋 When the model is the truth, undo is an assignment, paste is a filter, markdown is a splice and collaboration is a list of changes — all of them small pure functions you can fuzz against a dumber implementation until you believe them.
