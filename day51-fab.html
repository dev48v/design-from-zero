DesignFromZero · Day 51

Floating Action Button — a single high-emphasis action lifted off the page into a rounded button pinned to a corner, always in reach. Tap it and it becomes a speed-dial: the + morphs into a close ×, a scrim drops over the screen to focus attention, and a short stack of labelled sub-actions fans out with a staggered spring. It can anchor bottom-right or bottom-left, and swap to an extended shape that pairs the icon with a word. Built as a real <button> with aria-expanded, a role="menu" of items, Escape-to-close and managed focus — the primary-action affordance you have tapped a thousand times, rebuilt from scratch in one file.

The corner button that fans out — compose, create, add, share.

A FAB promotes the one action a screen is really about — the new mail, the new event, the new post — into a button that floats above the content, pinned to a corner so it never scrolls away. A speed-dial gives that one button a small menu: press it and it morphs its plus into an ×, throws a scrim over the screen to say “pick one”, and staggers a handful of labelled mini-buttons into view. Try it on the phone mock-up: tap the button to open and close, then use the controls to move it bottom-left, switch on the extended shape, dial the number of actions, and flip the trigger between click and hover. It is a real <button>: Tab to it, Enter to open, ↑↓ through the items, Esc to close.

The whole thing is one <button> and a list. Opening flips a single boolean: it sets aria-expanded, adds an .open class that the CSS animates, shows the scrim, and walks the items setting a transition-delay so they cascade — nearest the FAB first on the way out, top-down on the way back. This panel is a pure read-out of the widget’s state. aria-expanded is the exact attribute a screen reader announces — watch it flip with the button. Focus shows where the keyboard is: on the FAB when closed, on a menu item when open, and back on the FAB after Esc. One boolean drives the class, the aria, the scrim and this whole card.

Gmail’s compose, Google Maps’ add-a-place, Docs’ new file, almost every Android app’s bottom-right circle — the same idea each time: one action, promoted. Keep it to a single primary action (or a tight speed-dial of related ones), anchor it to a thumb-friendly corner, morph the icon so open/closed is unmistakable, label the mini-buttons because an icon alone is a guess, and wire the a11y — a real button, aria-expanded, a menu of items, Esc and focus return. Get those and the corner button feels native, not bolted on.

🔨 Build it yourself

    
A FAB is a button anchored to a corner; a speed-dial is that button plus a list of actions it reveals. We start from the markup and positioning, make the icon morph from plus to close, render the labelled sub-actions, drive everything from one open boolean wired to aria-expanded, add the staggered reveal, drop a scrim with tap-and-Esc dismissal, support bottom-right / bottom-left, add the extended shape, then finish with keyboard & focus and the design rules for when to use one. Vanilla HTML, CSS and JS — no framework, no dependencies.

    
    
      
  1. 
        
    1
    The FAB — a button pinned to a corner
    
        
    A FAB is not a special widget, it is a plain <button> taken out of the document flow and anchored to a corner of its container with position:absolute (or fixed for a whole page). Give it a comfortable tap size — 56px is the Material standard — a rounded shape and a lift-off shadow so it reads as floating above the content. Wrap it in a positioned container so the speed-dial items can stack relative to the same corner.
    
        
    <div class="fab-wrap pos-br">            <!-- anchored bottom-right -->
  <div class="sd-actions" role="menu"></div>
  <button class="fab" aria-haspopup="menu"
          aria-expanded="false" aria-controls="sdActions">
    <svg class="fab-icon">…plus…</svg>
  </button>
</div>

.fab-wrap { position:absolute; bottom:22px; z-index:5; }
.fab-wrap.pos-br { right:22px; align-items:flex-end; }
.fab { width:56px; height:56px; border-radius:18px;
       box-shadow:0 8px 20px rgba(79,70,229,.45); }
    
      
    2. 
      
  2. 
        
    2
    Morph the icon — a plus that spins into a close
    
        
    Open and closed must look different, and the cheapest, most delightful way is to reuse the same icon. A plus rotated 45° is already an ×; rotate a touch further for momentum. Keep a single + SVG and toggle a class that applies transform:rotate(135deg) with a spring easing. No icon swap, no second asset — one glyph, one transition.
    
        
    <svg class="fab-icon" viewBox="0 0 24 24"
     stroke="currentColor" stroke-width="2.4">
  <path d="M12 5v14M5 12h14"/>      <!-- a plus -->
</svg>

.fab-icon { transition: transform .3s cubic-bezier(.2,.8,.2,1.4); }
.fab.open .fab-icon { transform: rotate(135deg); } /* + -> x */
    
      
    3. 
      
  3. 
        
    3
    The sub-actions — labelled mini buttons
    
        
    A speed-dial is a short list of related actions, each a mini button plus a text label — an icon alone is a riddle. Render them from data so the count is adjustable. Each mini button is a role="menuitem", starts tabindex="-1" (the roving-focus pattern), and carries an aria-label. Stack them in a column above the FAB; the label sits on the side away from the screen edge.
    
        
    const ACTIONS = [
  { id:'edit',  label:'Edit',      svg:'…' },
  { id:'share', label:'Share',     svg:'…' },
  { id:'photo', label:'Add photo', svg:'…' },
];
sdActions.innerHTML = ACTIONS.slice(0, count).map(a => `
  <div class="sd-item">
    <button class="sd-btn" role="menuitem" tabindex="-1"
            data-id="${a.id}" aria-label="${a.label}">${a.svg}</button>
    <span class="sd-label">${a.label}</span>
  </div>`).join('');
    
      
    4. 
      
  4. 
        
    4
    One boolean drives everything
    
        
    All the state is a single open flag. A setOpen(v) function is the one place that mutates it: it toggles the .open class (CSS animates the rest), writes aria-expanded so assistive tech is always correct, shows or hides the scrim, and moves focus. Everything else — a click on the FAB, the scrim, Esc, a menu item — just calls setOpen. Keep mutation in one function and the component stays honest.
    
        
    let open = false;
function setOpen(v, focusItem){
  open = v;
  fabWrap.classList.toggle('open', v);
  fab.classList.toggle('open', v);
  fab.setAttribute('aria-expanded', String(v));   // a11y truth
  scrim.classList.toggle('show', v);
  stagger(v);                                      // step 5
  if (v && focusItem) items()[0].focus();
  else if (!v) fab.focus();                        // return focus
}
fab.addEventListener('click', () => setOpen(!open, true));
    
      
    5. 
      
  5. 
        
    5
    Stagger the reveal
    
        
    All items appearing at once feels cheap; a cascade feels crafted. The .open class fades and springs each .sd-item from a small offset back to place — the CSS does the motion. To sequence them, set each item’s transition-delay in JS: on the way out, the item nearest the FAB goes first; on the way back, reverse it so the row closest to the button is last to leave. Frame-independent, pure CSS transition, JS only picks the delays.
    
        
    .sd-item { opacity:0; transform:translateY(12px) scale(.8);
  transition:opacity .2s, transform .2s cubic-bezier(.2,.9,.3,1.3); }
.fab-wrap.open .sd-item { opacity:1; transform:none; }

function stagger(opening){
  const list = items();                    // DOM order: top -> bottom
  list.forEach((el, i) => {
    const order = opening ? (list.length - 1 - i) : i; // near-FAB first out
    el.style.transitionDelay = (order * cfg.stagger) + 'ms';
  });
}
    
      
    6. 
      
  6. 
        
    6
    The scrim — focus, and tap-to-dismiss
    
        
    When the dial is open, a translucent scrim covers the screen. It does two jobs: it dims the busy content so the choices stand out, and it becomes one big dismiss target — a tap anywhere that is not an action closes the menu. Fade it with the same open state, and give it pointer-events:none when hidden so it never blocks the app underneath. Add Esc as the keyboard equivalent.
    
        
    .scrim { position:absolute; inset:0; z-index:4;
  background:rgba(15,23,42,.34); opacity:0; pointer-events:none;
  transition:opacity .25s; }
.scrim.show { opacity:1; pointer-events:auto; }

scrim.addEventListener('click', () => setOpen(false));
document.addEventListener('keydown', e => {
  if (e.key === 'Escape' && open) setOpen(false);   // Esc closes
});

  7. 
        
    7
    Positions — bottom-right or bottom-left
    
        
    A FAB lives in a bottom corner for thumb reach. Swapping corners is one class: .pos-br pins right and right-aligns the stack, .pos-bl pins left and left-aligns it. The only subtlety is the label side — it must sit toward the screen interior, away from the edge — which a flex-direction flip handles per position.
    
        
    .fab-wrap.pos-br { right:22px; align-items:flex-end; }
.fab-wrap.pos-bl { left:22px;  align-items:flex-start; }

/* keep the label on the inner side, never off-screen */
.fab-wrap.pos-br .sd-item { flex-direction:row-reverse; } /* label left */
.fab-wrap.pos-bl .sd-item { flex-direction:row; }         /* label right */

setPos('bl');  // fabWrap.className = 'fab-wrap pos-' + p;

  8. 
        
    8
    The extended FAB — icon plus a word
    
        
    When a screen has room and the action deserves a name, the extended FAB pairs the icon with a short label (“Create”, “Compose”). It is the same button that simply grows: reveal the text and let the width animate from the icon-only size. Animate max-width (not width:auto, which will not transition) so it slides open smoothly.
    
        
    <button class="fab">
  <svg class="fab-icon">…</svg>
  <span class="fab-text">Create</span>
</button>

.fab-text { max-width:0; opacity:0; overflow:hidden;
  transition:max-width .28s cubic-bezier(.2,.8,.2,1), opacity .2s; }
.fab.extended { padding:0 22px; }
.fab.extended .fab-text { max-width:120px; opacity:1; }

  9. 
        
    9
    Keyboard & focus — the a11y that makes it real
    
        
    It only counts as a menu if the keyboard agrees. The FAB carries aria-haspopup="menu" and aria-expanded; the container is role="menu", each item a role="menuitem". On open, move focus to the first item; ↑/↓ roam with wraparound (the roving-tabindex pattern), Esc closes and returns focus to the FAB so the user is never dropped. Respect prefers-reduced-motion by collapsing the transitions.
    
        
    sdActions.addEventListener('keydown', e => {
  const list = items(); const i = list.indexOf(document.activeElement);
  if (e.key === 'ArrowDown'){ e.preventDefault();
    list[(i + 1) % list.length].focus(); }
  else if (e.key === 'ArrowUp'){ e.preventDefault();
    list[(i - 1 + list.length) % list.length].focus(); }
  else if (e.key === 'Escape'){ setOpen(false); }  // focus back to FAB
});

    When to use one — and when not to
    
        
    A FAB is for the single most important action of a screen — the thing you came to do. Use it when there is a clear primary action (compose, create, add) and, at most, a tight speed-dial of closely related shortcuts. Do not make it a junk drawer of unrelated commands, do not float two FABs on one screen, do not hide destructive actions behind it, and never let it cover content the user needs (raise it above a snackbar). If the actions are many or equal in weight, a toolbar or menu is the honest choice. One promoted action, done unmistakably — that is the whole point.
    
        
    // GOOD: one primary action, promoted
<button class="fab" aria-label="Compose">…</button>

// GOOD: a tight dial of related shortcuts
[ Edit, Add photo, Share ]      // 2-5, all related

// AVOID: a dumping ground / two FABs / hidden delete
[ Settings, Help, Delete all, Log out, Print, ... ]  // use a menu

if (matchMedia('(prefers-reduced-motion: reduce)').matches){
  /* CSS already collapses the transitions */
}
