DesignFromZero · Day 60

Spreadsheet grid — a Google-Sheets-style editable grid with a real formula engine. The sheet is not a 2-D array of DOM nodes: it is a sparse Map keyed by A1 address where each cell keeps two fields — the raw text you typed and the val the engine computed — which is exactly why the cell shows 182,760 while the formula bar shows =SUM(E2:E8). Anything starting with = is run through a hand-written pipeline: a tokenizer splits =ROUND(E10/$B$12,2) into numbers, strings, refs and operators, a Pratt parser turns that flat list into a tree with correct precedence and parentheses, and a tree-walking evaluator produces a number, a string, a boolean or an error value — no eval() anywhere. The refs found while parsing become edges in a dependency graph, so editing one cell walks its transitive dependents, sorts just those in topological order (Kahn) and recalculates them once each — never the whole sheet, never twice, and anything left with a non-zero in-degree is a cycle and gets #CIRC!. Errors are first-class values that propagate: #DIV/0!, #NAME?, #REF!, #VALUE!. Selection is an anchor + focus rectangle, never a list of cells; the fill handle and copy/paste rewrite formulas through relative reference translation so =A1*2 filled down becomes =A2*2 while $A$1 stays anchored; and the editor is one input element that is repositioned, never re-created mid-edit, so the caret survives every render. Full keyboard model — ←↑→↓ Enter Tab F2 Esc Shift+arrows Ctrl+A/C/V/Z. No libraries, no images — every icon is inline SVG.

Live state — raw vs computed

A cell stores raw (what you typed) and val (what the engine produced). The grid paints val, the formula bar paints raw. Two fields, one edit — that single split is what makes a spreadsheet a spreadsheet.

Every spreadsheet, every reactive signal library and every build system you have used is this same shape: values with declared inputs, a graph built from those declarations, and a topological pass that touches each node exactly once. Model it that way and incremental recalculation, cycle detection and error propagation stop being features — they are consequences. 🔨 Build it yourself

    
A spreadsheet looks like the hardest component on the list, but it is four small machines bolted together. We store the sheet as a sparse Map keyed by A1 address, write the address math that converts between "AB10" and (row, col), give every cell a raw and a computed field, then build the engine properly: a tokenizer, a Pratt parser with real precedence, and a tree-walking evaluator with functions and error values. The refs the parser found become a dependency graph, so one edit recalculates only its transitive dependents in topological order and anything left over is a cycle. Then the UI: render from state, one reusable editor input, an anchor+focus selection, and a fill handle that rewrites relative references. Vanilla HTML, CSS and JS — no framework, no dependencies, no eval().

    Address math — the base-26-ish column letters
    
        
    Everything downstream needs to move between "AB10" and (row 9, col 27). Column letters look like base 26 but there is no zero digit — after Z comes AA, not BA — so both directions carry a ±1. Get this pair right once, test it over a sweep, and never think about it again.
    
        
    function colName(c){                 // 0 -> A, 25 -> Z, 26 -> AA
  let s = "", n = c + 1;
  while (n > 0){
    const r = (n - 1) % 26;
    s = String.fromCharCode(65 + r) + s;
    n = Math.floor((n - 1) / 26);
  }
  return s;
}
function colIndex(s){                // "A" -> 0, "AA" -> 26
  let n = 0;
  const up = String(s).toUpperCase();
  for (let i = 0; i < up.length; i++) n = n * 26 + (up.charCodeAt(i) - 64);
  return n - 1;
}
const addrOf = (r, c) => colName(c) + (r + 1);

    2
    The sheet is a sparse Map, and a cell has two fields
    
        
    Do not allocate rows × cols of anything. Store only the cells somebody touched, keyed by address, and keep raw (what was typed) separate from val (what the engine produced). That one split is the whole illusion: the grid paints val, the formula bar paints raw. A missing key is a blank cell — and blank is a real value, not undefined.

    Tokenize the formula — and disambiguate LOG10 from a cell
    
        
    The scanner walks the text once and emits numbers, quoted strings ("" is an escaped quote), identifiers, operators and punctuation. Identifiers are ambiguous: SUM is a function, A1 is a reference, and LOG10 looks exactly like a cell. Real spreadsheets resolve it the same way we do — peek at the next non-space character: a ( means function, otherwise test it against the address pattern.
    
        
    const ADDR_RE = /^(\$?)([A-Za-z]{1,3})(\$?)([1-9][0-9]{0,6})$/;

if (/[A-Za-z_$]/.test(ch)){
  while (i < s.length && /[A-Za-z0-9_$.]/.test(s[i])) i++;
  const text = s.slice(start, i), up = text.toUpperCase();
  let j = i; while (s[j] === " ") j++;              // peek past spaces
  if (up === "TRUE" || up === "FALSE") push("bool", up === "TRUE");
  else if (s[j] === "(")               push("func", up);   // SUM(  LOG10(
  else if (ADDR_RE.test(text))         push("ref");        // A1  $B$12
  else                                 push("name", up);   // -> #NAME?
}

  4. 
        
    4
    A Pratt parser gives you precedence for free
    
        
    One binding-power table plus a five-line loop is the entire grammar. Each operator says how tightly it binds; the loop keeps absorbing operators at least that tight and recurses with bp + 1, which makes everything left-associative — including ^, because Sheets evaluates 2^3^2 as 64, not the mathematician's 512. Unary minus is parsed above ^ so -2^2 is 4, matching Excel.
    
        
    const BINP = { "=":1,"<>":1,"<":1,">":1,"<=":1,">=":1, "&":2, "+":3,"-":3, "*":4,"/":4, "^":5 };

function parseExpr(minp){
  let left = parseUnary();
  for (;;){
    const t = peek();
    if (!t || t.type !== "op") break;
    const bp = BINP[t.text];
    if (bp === undefined || bp < minp) break;
    next();
    const right = parseExpr(bp + 1);      // +1 => left-associative
    left = { t:"bin", op:t.text, l:left, r:right };
  }
  return left;
}

  5. 
        
    5
    A range is a rectangle, not a list — until a function asks
    
        
    A1:C3 parses into two corners. Keep it that way in the tree and expand it to nine addresses only when a function flattens its arguments; that keeps =A1:C3 + 1 honestly an error (#VALUE!) instead of silently guessing. Normalise while expanding, so C3:A1 and A1:C3 are the same nine cells.
    
        
    function rangeAddrs(a, b){
  const r1 = Math.min(a.r, b.r), r2 = Math.max(a.r, b.r);
  const c1 = Math.min(a.c, b.c), c2 = Math.max(a.c, b.c);
  const out = [];
  for (let r = r1; r <= r2; r++)
    for (let c = c1; c <= c2; c++) out.push(addrOf(r, c));
  return out;                       // A1:C3 -> 9 addresses, always in order
}

    Evaluate the tree — and make errors first-class values
    
        
    An error is not an exception, it is a value: { e:"#DIV/0!" }. Check for it at the top of every operator and every function argument and return it unchanged, and propagation is automatic — a cell reading a broken cell breaks the same way, all the way down the graph. Division guards zero, an unknown function is #NAME?, and text where a number was needed is #VALUE!.

const isErr = v => !!v && typeof v === "object" && typeof v.e === "string";

  if (n.op === "&") return strOf(a) + strOf(b);
  const x = numOf(a); if (isErr(x)) return x;             // "abc" -> #VALUE!
  const y = numOf(b); if (isErr(y)) return y;
  if (n.op === "/") return y === 0 ? err("#DIV/0!") : x / y;
  ...
}

  7. 
        
    7
    Parsing hands you the dependency graph
    
        
    Walk the tree you already built and collect every ref (ranges expanded). Those are the cell's precedents; store the reverse map too, so every cell knows who reads it. Rebuild both on each edit — unhook the old edges first, or a deleted reference will keep firing recalculations forever.
    
        
    function refsOf(ast){
  const out = [];
  (function walk(n){
    if (!n || typeof n !== "object") return;
    if (n.t === "ref")   return void out.push(addrOf(n.a.r, n.a.c));
    if (n.t === "range") return void rangeAddrs(n.a, n.b).forEach(a => out.push(a));
    if (n.t === "bin")   { walk(n.l); walk(n.r); return; }
    if (n.t === "un" || n.t === "pct") return walk(n.x);
    if (n.t === "call")  n.args.forEach(walk);
  })(ast);
  return Array.from(new Set(out));
}
// unhook old edges, then: refs.forEach(d => dependents.get(d).add(addr));

  8. 
        
    8
    Recalculate in topological order — leftovers are the cycle
    
        
    Collect the edited cell plus its transitive dependents, count in-degrees inside that set only, and drain with Kahn's algorithm. Every cell is evaluated exactly once and always after its inputs. The elegant part is free cycle detection: if the queue empties while cells remain, those cells can never be ordered — that is the definition of a cycle — so mark them #CIRC!.
    
        
    function recalcSet(set){
  const order = [], indeg = new Map();
  set.forEach(a => indeg.set(a, 0));
  set.forEach(a => (cellAt(a)?.refs || []).forEach(d => {
    if (set.has(d)) indeg.set(a, indeg.get(a) + 1);
  }));
  const q = [...set].filter(a => indeg.get(a) === 0).sort();
  while (q.length){
    const a = q.shift(); order.push(a);
    (SHEET.dependents.get(a) || []).forEach(d => {
      if (!set.has(d)) return;
      indeg.set(d, indeg.get(d) - 1);
      if (indeg.get(d) === 0) q.push(d);
    });
  }
  order.forEach(a => { const c = cellAt(a); if (c && c.ast) c.val = evalNode(c.ast, CTX); });
  set.forEach(a => { if (order.indexOf(a) < 0) cellAt(a).val = err("#CIRC!"); });
  return order;
}

    9
    Fill and copy rewrite the text — relative reference translation
    
        
    Dragging the fill handle does not copy a value, it copies a formula shifted by the row/column delta. Re-tokenize the raw text, shift only the ref tokens, and splice them back from the end so earlier positions stay valid. A $ pins its half of the address; falling off the sheet becomes #REF!. Everything else — strings, function names, spacing — is left byte-for-byte alone.
    
        
    function translateFormula(raw, dr, dc){
  if (typeof raw !== "string" || raw[0] !== "=") return raw;
  const body = raw.slice(1), toks = tokenize(body);
  let out = body;
  for (let i = toks.length - 1; i >= 0; i--){          // back to front
    const t = toks[i];
    if (t.type !== "ref") continue;
    out = out.slice(0, t.pos) + shiftRef(t.text, dr, dc) + out.slice(t.pos + t.text.length);
  }
  return "=" + out;
}
// =A1*2  filled down 1  ->  =A2*2
// =A$1*2 filled down 1  ->  =A$1*2      (row pinned)
// =$A$1  filled anywhere -> =$A$1       (both pinned)

    Selection is a rectangle; editing is a state machine
    
        
    Keep two points — anchor (where the selection started) and focus (where the arrow keys are) — and derive the rectangle by min/max, so shift-arrow works in every direction without a special case. Editing is idle → editing → commit | cancel with the pre-edit raw text stashed, because Esc must put it back. Crucially, the editor is one persistent input that gets moved and shown — re-creating it mid-edit would destroy the caret on every keystroke.
    
        
    const normRect = (a, f) => ({
  r1: Math.min(a.r, f.r), r2: Math.max(a.r, f.r),
  c1: Math.min(a.c, f.c), c2: Math.max(a.c, f.c)
});
