🔨 Build it yourself

    
A date-range picker is a calendar you draw plus a two-click state machine. We start from the math — leap years and days-in-month, the first-weekday offset — lay a month into a 7-column grid of blanks and numbers, render two months that share one clock, give every day a monotonic integer key for comparison, wire the start-then-end selection with an auto-swap, add the hover preview, paint start / in-range / end from the two keys, compute the inclusive day count, drive the presets as pure date arithmetic, and finish with keyboard + a11y. Vanilla HTML, CSS and JS — no framework, no dependencies.

    1
    Days in a month — the leap-year rule
    
        
    The whole calendar rests on two facts: how many days a month has, and which day of the week it starts on. Days-per-month is a fixed table — except February, which is 29 in a leap year. A leap year is divisible by 4, but not by 100 unless also by 400 (so 2000 is a leap year, 1900 is not).
    
        
    function isLeap(y){
  return (y % 4 === 0 && y % 100 !== 0) || (y % 400 === 0);
}
function daysInMonth(y, m){   // m is 0-based: 0 = Jan
  return [31, isLeap(y) ? 29 : 28, 31,30,31,30,31,31,30,31,30,31][m];
}
daysInMonth(2024, 1); // Feb 2024 -> 29    daysInMonth(2023,1) -> 28

    The first-weekday offset positions day 1
    
        
    A month grid is not filled from the top-left — day 1 sits under its real weekday. new Date(y, m, 1).getDay() gives that column (0 = Sunday). That number is how many blank cells to emit before the first number, so every date lands in the correct column.
    
        
    function firstWeekday(y, m){
  return new Date(y, m, 1).getDay();   // 0=Sun .. 6=Sat
}
// March 2024 starts on a Friday -> offset 5 -> 5 blanks, then "1"
const offset = firstWeekday(2024, 2); // 5

    Lay a month into a 7-column grid
    
        
    A CSS grid of seven columns. Emit the Su…Sa header, then offset empty cells, then a real <button> for each day 1..N. Numbers go in with textContent; stamp each button with its y / m / d so a click knows exactly which date it is.
    
        
    function buildGrid(el, y, m){
  el.innerHTML = "";
  WD.forEach(w => el.appendChild(cell("dr-wd", w)));      // Su..Sa
  for (let i = 0; i < firstWeekday(y, m); i++)
    el.appendChild(cell("dr-blank"));                     // leading gaps
  for (let d = 1; d <= daysInMonth(y, m); d++){
    const b = document.createElement("button");
    b.className = "dr-day"; b.dataset.y = y; b.dataset.m = m; b.dataset.d = d;
    b.innerHTML = '<span class="dr-num"></span>';
    b.firstChild.textContent = d;                         // data as textContent
    el.appendChild(b);
  }
}

    Two months, one clock
    
        
    The left month is (viewY, viewM); the right is simply the month after — with a year rollover when December wraps to January. Prev / next shift the left month by one and the right follows, so the pair always stays adjacent.
    
        
    function nextMonth(y, m){ return m === 11 ? {y:y+1, m:0} : {y, m:m+1}; }
function render(){
  const R = nextMonth(viewY, viewM);
  title0.textContent = MONTHS[viewM] + " " + viewY;
  title1.textContent = MONTHS[R.m] + " " + R.y;
  buildGrid(grid0, viewY, viewM);
  buildGrid(grid1, R.y, R.m);
  paint();                       // apply the range classes
}

    5
    One integer key to compare any two days
    
        
    Comparing dates as objects is awkward. Fold each into a single number — y×10000 + (m+1)×100 + d — and because the components never overflow their slots, that number is monotonic: Mar 31 (20240331) is less than Apr 1 (20240401). One < now works cleanly across a month boundary.
    
        
    function keyOf(y, m, d){ return y*10000 + (m+1)*100 + d; }
keyOf(2024,2,31) < keyOf(2024,3,1);   // true  (Mar 31 < Apr 1)

// day count is inclusive, via UTC so DST never shifts it
function dayCount(a, b){
  return Math.round((Date.UTC(b.y,b.m,b.d) - Date.UTC(a.y,a.m,a.d)) / 864e5) + 1;
}

    The two-click state machine
    
        
    Two variables hold everything: rangeStart and rangeEnd. If there is no start (or a full range already), a click begins fresh — set start, clear end. Otherwise the click sets the end, and if it lands before the start the two swap so the range always reads left-to-right.
    
        
    function pick(y, m, d){
  const p = {y, m, d};
  if (!rangeStart || rangeEnd){          // start a new range
    rangeStart = p; rangeEnd = null;
  } else {                               // set the end...
    if (keyOf(y,m,d) < keyOf(rangeStart.y, rangeStart.m, rangeStart.d)){
      rangeEnd = rangeStart; rangeStart = p;   // ...swapping if earlier
    } else {
      rangeEnd = p;
    }
  }
  render();
}

    Hover preview of the pending range
    
        
    Between the first and second click, the range is provisional. Track a hover day; while a start exists but no end, mousing over a cell paints the band from the start to the hovered day. Leaving the grid clears it — only paint() re-runs, so nothing rebuilds.
    
        
    btn.addEventListener("mouseenter", () => {
  if (rangeStart && !rangeEnd){ hover = {y, m, d}; paint(); }
});
cal.addEventListener("mouseleave", () => { hover = null; paint(); });

    Paint: start, in-range, end from two keys
    
        
    Painting reduces the state to a lo and hi key — from the committed range, or from start+hover during preview. Then every cell answers three cheap questions: am I lo (start), am I hi (end), am I strictly between (in-range)? The CSS half-band + circle does the rest, and a single day where lo === hi is just a lone circle.
    
        
    function paint(){
  let lo = null, hi = null;
  if (rangeStart && rangeEnd){ lo = keyOf2(rangeStart); hi = keyOf2(rangeEnd); }
  else if (rangeStart && hover){ lo = Math.min(...); hi = Math.max(...); }
  else if (rangeStart){ lo = hi = keyOf2(rangeStart); }   // lone start
  dayCells.forEach(c => {
    const k = +c.dataset.key;
    c.classList.toggle("range-start", lo !== null && k === lo && lo !== hi);
    c.classList.toggle("range-end",   lo !== null && k === hi && lo !== hi);
    c.classList.toggle("single",      lo !== null && k === lo && lo === hi);
    c.classList.toggle("in-range",    lo !== null && k > lo && k < hi);
  });
}

    Presets are just date arithmetic
    
        
    A preset is not special — it computes two dates and writes the same rangeStart / rangeEnd, then points the view at the start month so the result is visible. “Last 7 days” is today minus 6 to today; “This month” is the 1st to day 0 of next month (which is the last day of this one).
    
        
    const iso = dt => ({ y:dt.getFullYear(), m:dt.getMonth(), d:dt.getDate() });
function last7(){
  const e = new Date(), s = new Date(); s.setDate(s.getDate() - 6);
  setRange(iso(s), iso(e), "Last 7 days");     // 7 days inclusive
}
function thisMonth(){
  const t = new Date();
  setRange({y:t.getFullYear(), m:t.getMonth(), d:1},
           iso(new Date(t.getFullYear(), t.getMonth()+1, 0)), "This month");
}

    Keyboard & accessibility
    
        
    Days are real <button>s, so Tab and Enter come for free. A roving tabindex keeps one day focusable; the arrows move a focus date by ±1 (day) or ±7 (week) with real date math, shifting the view if the focus leaves the two months, then move DOM focus to the new cell. Grids get role="grid", the output is aria-live so a screen reader hears the chosen range.
    
        
    const STEP = { ArrowLeft:-1, ArrowRight:1, ArrowUp:-7, ArrowDown:7 };
cal.addEventListener("keydown", e => {
  if (e.key in STEP){
    e.preventDefault();
    const dt = new Date(focus.y, focus.m, focus.d + STEP[e.key]); // real math
    focus = iso(dt); ensureVisible(focus); render();
    cellFor(focus).focus();               // move the roving focus
  } else if (e.key === "Enter" || e.key === " "){
    e.preventDefault(); pick(focus.y, focus.m, focus.d);
  }
});
