DesignFromZero · Day 59

Gmail inbox — a real mail client driven by one flat array of message objects. Every folder in the sidebar is a predicate, not a copy: Inbox, Starred, Snoozed, Sent, Drafts, Spam and Trash all read the same array and simply keep the rows that match, so archiving a mail is one field change (folder = "archive") and the row leaves the view without anything being deleted — which is exactly why Undo is a snapshot-and-restore, not a re-fetch. On top of that array sits a tiny state object — folder, tab, query, a Set of selected ids, a keyboard cursor and the open message — and one render() recomputes the filter chain (folder → category tab → search text), the row list, the sidebar unread counts and the toolbar from it. Unread is data (bold + white row) not a hand-toggled class; the star and checkbox are real buttons that stopPropagation() so they never open the mail; the hover action rail (archive · delete · mark unread · snooze) swaps in where the date sits; the select-all box is genuinely tri-state via indeterminate; and the reading pane is a responsive split view that becomes a full-screen reader below 760px through a ResizeObserver, not a media query. Full Gmail keyboard model — jkxse#u/?. No libraries, no images — every icon is inline SVG.

One array, one filter chain — an inbox that actually works.

Hover a row to reveal the action rail, click the star, tick the checkbox to select (the header box goes tri-state), archive or delete and watch the row leave — then hit Undo in the toast. Click a mail to open the split reading pane. Switch folders in the sidebar, flip the Primary / Social / Promotions tabs, or search. Keyboard works too: j/k move, x select, s star, e archive, # delete, Enter open, u back, ? for the sheet. Drag the browser narrow — the same component becomes a phone inbox.

Real component — select, star, archive, undo, search, open, resize. Not one pixel is a screenshot.

Live state — the list is derived

Nothing is ever removed from MESSAGES. Archive and Delete write a folder field; the row disappears only because the folder predicate stopped matching it — which is what makes Undo a one-line restore.

Every mail client, task list and CRM table you have used is this same shape: one collection, a chain of filters that derives what is on screen, a selection set for bulk actions, and mutations that flip a field rather than splicing an array. Model it that way and multi-select, undo, unread counts and search stop being features — they are consequences.

🔨 Build it yourself

    
Gmail looks enormous, but the whole thing is one array plus a filter chain. We define the message model, make every folder a predicate, keep a tiny state object, render rows from the derived list, add a Set-based selection with a tri-state select-all, make star and checkbox behave inside a clickable row, reveal the hover action rail, implement archive as a field write so Undo is free, wire the split reading pane that collapses on narrow widths, and finish with the keyboard model. Vanilla HTML, CSS and JS — no framework, no dependencies, no images.

    The message model — one flat array
    
        
    A mail is a plain object. Note what is data: unread, starred, folder and category. Bold rows, blue counts and which folder a mail lives in are all read off these fields — never toggled by hand on a DOM node.
    
        
    const MESSAGES = [
  { id:1, from:"Vercel", email:"ship@vercel.com",
    subject:"Deployment ready", snippet:"dev48v-website is live in 42s",
    body:["Your production deployment finished."],
    dt:"2026-08-11 09:42", unread:true, starred:false, important:true,
    category:"primary", folder:"inbox", snoozed:false, attachments:[] },
  // ...
];
const byId = id => MESSAGES.find(m => m.id === id);

    2
    Folders are predicates, not seven arrays
    
        
    One function decides whether a message belongs in a folder. Starred is a flag match, not a bucket — so a mail can be in Inbox and Starred at once without being stored twice, and un-starring it needs no bookkeeping anywhere else.
    
        
    function matches(m, folder){
  switch (folder){
    case "inbox":   return m.folder === "inbox" && !m.snoozed;
    case "starred": return m.starred && m.folder !== "trash" && m.folder !== "spam";
    case "snoozed": return m.snoozed;
    case "sent":    return m.folder === "sent";
    case "drafts":  return m.folder === "drafts";
    case "spam":    return m.folder === "spam";
    case "trash":   return m.folder === "trash";
    case "archive": return m.folder === "archive";
  }
  return false;
}

    One state object + one filter chain
    
        
    visible() is the only place that decides what is on screen: folder, then the category tab (Inbox only), then the search text, then a newest-first sort. Because it is recomputed on every render, the list can never lag behind the data.
    
        
    const state = { folder:"inbox", tab:"primary", query:"",
                sel:new Set(), cursor:0, open:null };

function visible(){
  let list = MESSAGES.filter(m => matches(m, state.folder));
  if (state.folder === "inbox") list = list.filter(m => m.category === state.tab);
  const q = state.query.trim().toLowerCase();
  if (q) list = list.filter(m =>
    (m.from + " " + m.email + " " + m.subject + " " + m.snippet).toLowerCase().includes(q));
  return list.sort((a, b) => b.dt.localeCompare(a.dt));
}

    Rendering a row — unread is data
    
        
    The row builds its classes from the message. unread gives the white background and bold text; picked comes from the selection Set; cursor from the keyboard index. No handler ever writes style.fontWeight — it flips a field and re-renders.
    
        
    function rowEl(m, i){
  const row = el("div", "gm-row"
    + (m.unread ? " unread" : "")
    + (state.sel.has(m.id) ? " picked" : "")
    + (i === state.cursor ? " cursor" : "")
    + (m.id === state.open ? " open" : ""));
  row.onclick = () => openMail(m);
  return row;
}

    Selection is a Set of ids — and select-all is tri-state
    
        
    Store ids, not indexes or DOM nodes, so a sort or a filter can never point selection at the wrong mail. The header box has three states: none, some (indeterminate), all. Prune the Set after every mutation so an archived mail cannot stay selected.
    
        
    function toggleSel(id){ state.sel.has(id) ? state.sel.delete(id) : state.sel.add(id); render(); }

function headerBoxState(){
  const rows = visible(), n = rows.filter(m => state.sel.has(m.id)).length;
  return n === 0 ? "none" : n === rows.length ? "all" : "some";   // some => indeterminate
}

function prune(){                                  // after archive / delete / filter change
  const ok = new Set(visible().map(m => m.id));
  [...state.sel].forEach(id => { if (!ok.has(id)) state.sel.delete(id); });
}

    6
    Controls inside a clickable row — stopPropagation
    
        
    The whole row opens the mail, but the star and checkbox sit inside it. Without stopPropagation() every star click would also open the conversation. Keep them real <button>s with aria-pressed so they stay keyboard-reachable and announce their state.
    
        
    const star = el("button", "gm-icb star" + (m.starred ? " on" : ""));
star.setAttribute("aria-pressed", m.starred);
star.setAttribute("aria-label", m.starred ? "Starred" : "Not starred");
star.onclick = (e) => {
  e.stopPropagation();          // <- the row's onclick must not fire
  m.starred = !m.starred;
  render();
};

    The hover action rail replaces the date
    
        
    Gmail hides four buttons where the date is and swaps them in on hover — pure CSS, no JS. Build the buttons always (so they exist for screen readers and keyboard users) and let CSS decide visibility; display:none on hover-out, never opacity:0, so a hidden button cannot be clicked by accident.

.gm-acts { display:none; }
.gm-row:hover .gm-date { display:none; }
.gm-row:hover .gm-acts { display:flex; }

/* touch / narrow: no hover, so keep the date and act from the reader */
.gm-app.narrow .gm-row:hover .gm-acts { display:none; }
.gm-app.narrow .gm-row:hover .gm-date { display:block; }

    8
    Archive is a field write — so Undo is a snapshot
    
        
    Never splice the array. Set folder = "archive" and the inbox predicate stops matching, so the row leaves. Because the object still exists, Undo is just writing the old field values back — one generic wrapper covers archive, delete, snooze and mark-read.
    
        
    const KEYS = ["folder","snoozed","unread","starred"];

function act(label, ids, mutate){
  const before = ids.map(id => {
    const m = byId(id), snap = { m };
    KEYS.forEach(k => snap[k] = m[k]);
    return snap;
  });
  ids.forEach(id => mutate(byId(id)));
  prune(); render();
  toast(label, () => {                       // the Undo button
    before.forEach(s => KEYS.forEach(k => s.m[k] = s[k]));
    render();
  });
}
act("Conversation archived", [m.id], x => { x.folder = "archive"; });
act("Moved to Trash",        [m.id], x => { x.folder = "trash";   });

    The reading pane is one state field, two layouts
    
        
    Opening a mail sets state.open and marks it read. Whether that shows as a split view or a full-screen reader is layout, not state. A ResizeObserver on the component — not a viewport media query — adds .narrow, so the widget adapts to its own width wherever it is embedded.
    
        
    function openMail(m){ m.unread = false; state.open = m.id; render(); }
function closeMail(){ state.open = null; render(); }

new ResizeObserver(([e]) => {
  app.classList.toggle("narrow", e.contentRect.width < 760);
}).observe(app);
    
        
    .gm-app.reading .gm-listpane { width:340px; flex:none; }   /* split  */
.gm-app.narrow.reading .gm-listpane { display:none; }      /* stacked */

    The keyboard model — a cursor and a map
    
        
    Gmail's shortcuts need one extra piece of state: a cursor index into the visible list. Then every key is a one-line entry in a map. Two guards matter — bail out while the user is typing in a field, and only handle keys while the component is hot (pointer over it or focus inside), so the page keeps its own keyboard.
    
        
    const KEYMAP = {
  j: () => moveCursor(+1),          k: () => moveCursor(-1),
  x: () => toggleSel(atCursor().id), s: () => toggleStar(atCursor()),
  e: () => archive([atCursor().id]), "#": () => trash([atCursor().id]),
  r: () => toggleRead(atCursor()),  b: () => snooze([atCursor().id]),
  Enter: () => openMail(atCursor()), u: closeMail, Escape: closeMail,
  "/": (e) => { e.preventDefault(); qInput.focus(); },
  z: undo,  "?": toggleKeySheet
};

document.addEventListener("keydown", (e) => {
  if (/^(INPUT|TEXTAREA)$/.test(e.target.tagName)) return;   // typing wins
  if (!hot && !app.contains(document.activeElement)) return; // scoped to us
  const fn = KEYMAP[e.key];
  if (fn){ e.preventDefault(); fn(e); }
});

    Because every view is derived, the sidebar's unread badges are one filter().length per folder, search is one more link in the chain, and the empty state is simply visible().length === 0. No counter to increment, no cache to bust — the price of a new feature is a predicate.

  return MESSAGES.filter(m => matches(m, folder) && m.unread).length;
}
