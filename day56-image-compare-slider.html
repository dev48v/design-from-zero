DesignFromZero · Day 56

Image Comparison Slider — two versions of the same picture stacked in one box with a draggable divider that wipes between them. The bottom layer (the AFTER) shows in full; the top layer (the BEFORE) is trimmed to the left of the divider by a single clip-path: inset(0 (100−pos)% 0 0), so moving the divider is nothing but rewriting one percentage. A pointer anywhere on the image maps to that percent — (clientX − left) / width × 100 — clamped to 0–100, and the same handler serves mouse and touch because it listens to unified pointer events with setPointerCapture so the drag survives leaving the frame. The round handle is a real role="slider": ←→ nudge it a percent (Shift/PageUp jump), Home/End snap to the edges, and aria-valuenow announces the split. A second demo flips the axis to a horizontal divider — the very same math with X swapped for Y. The sample scenes are drawn on a <canvas> (a flat, overcast unedited frame vs a golden-hour graded one) so the whole thing is self-contained — no libraries, no external image URLs.

Drag the divider — one percentage clips the top image and the two frames wipe apart.

A before/after slider is two pictures in one box and a divider that reveals more of one and less of the other. Everything is driven by a single number — the divider position as a percent. That number sets a clip-path on the top image (so it is trimmed exactly at the divider), positions the line and handle, fills the aria-valuenow, and writes the read-out. Drag anywhere on the image, tap to jump, or Tab to the handle and use ←→. Mouse and touch run through the identical pointer-event path. The card on the right is a pure read-out of that one number.

🔨 Build it yourself

    
A comparison slider is two layers in one box plus a divider driven by one percentage. We start by stacking two images in a clipped frame, reveal the top one with a single clip-path: inset, draw self-contained scenes on a canvas so there are no external files, map a pointer to a percent, clamp it to the track, funnel everything through one setPos that writes clip + divider + ARIA + read-out, wire drag once with pointer capture so mouse and touch share a path, make the handle a real keyboard slider, flip the axis for the horizontal variant, and finish with a11y. Vanilla HTML, CSS and JS — no framework, no dependencies, no image URLs.

    
    
      
  1. 
        
    1
    Two layers, one box
    
        
    Stack both images in a position:relative stage with overflow:hidden. Each layer is absolutely positioned and fills the box, so they line up pixel-for-pixel. DOM order is z-order: the AFTER layer is painted first (the full background); the BEFORE layer sits on top and is the one we will trim.
    
        
    .ic-stage  { position:relative; overflow:hidden; aspect-ratio:8/5; touch-action:none; }
.ic-canvas { position:absolute; inset:0; width:100%; height:100%; }

<div class="ic-stage">
  <canvas class="ic-after"></canvas>   <!-- full background -->
  <canvas class="ic-before"></canvas>  <!-- on top, gets clipped -->
</div>
    
      
    2. 
      
  2. 
        
    2
    The reveal is one clip-path
    
        
    To show only the left pos% of the top image, clip away its right side. clip-path: inset(top right bottom left) takes insets from each edge, so inset(0 (100−pos)% 0 0) trims (100−pos)% off the right and leaves the left pos% visible. At pos=50 the box is split down the middle; at 0 the top layer vanishes, at 100 it covers everything. No masks, no second canvas — one string.
    
        
    // reveal the left `pos`% of the BEFORE layer
before.style.clipPath = `inset(0 ${100 - pos}% 0 0)`;

// pos = 70  ->  inset(0 30% 0 0)  ->  left 70% shows BEFORE,
//                                      right 30% shows the AFTER underneath

  3. 
        
    3
    Draw the scenes on a canvas — no files
    
        
    To stay self-contained we do not load photos; we draw the same landscape twice with different palettes. One drawScene(ctx, W, H, after) lays the identical geometry — sky, sun, two mountain ridges, water — so the shapes register across the divider, and the after flag swaps a flat overcast grade for a warm golden-hour one. Same-seed math means both layers line up perfectly.
    
        
    function drawScene(ctx, W, H, after){
  const sky = ctx.createLinearGradient(0, 0, 0, H * 0.6);
  if (after){ sky.addColorStop(0,'#1e2a4a'); sky.addColorStop(.72,'#ff7a3d'); sky.addColorStop(1,'#ffd270'); }
  else      { sky.addColorStop(0,'#aab5c0'); sky.addColorStop(1,'#d8dee3'); }
  ctx.fillStyle = sky; ctx.fillRect(0, 0, W, H * 0.6);
  ridge(ctx, W, H*0.6, H*0.25, 1.1, after ? '#4a3568' : '#93a0ac');   // same geometry,
  ridge(ctx, W, H*0.6, H*0.37, 3.7, after ? '#2b1f42' : '#76828e');   // different grade
  // ...sun, water, vignette
}
    
      
    4. 
      
  4. 
        
    4
    Pointer → percent
    
        
    The core mapping. A pointer event carries a viewport clientX; subtract the stage's left edge (from getBoundingClientRect()) to get a local offset, divide by the stage width for a 0–1 fraction, times 100 for a percent. Because the rect is read live, it is correct no matter where the page has scrolled or how the stage was sized.
    
        
    function pctFromEvent(e){
  const rect = stage.getBoundingClientRect();
  const frac = (e.clientX - rect.left) / rect.width;   // 0 .. 1 across the box
  return frac * 100;                                   // -> percent
}
    
      
    5. 
      
  5. 
        
    5
    Clamp to the track
    
        
    A pointer can leave the frame while dragging, and an arrow key can push past an end. Every write goes through clamp(v, 0, 100) so the divider physically cannot escape its track — the clip-path stays valid, the handle stays on the line, and the value never reads a nonsense number. Clamp once, at the single choke-point, and nothing downstream has to worry.
    
        
    const clamp = (v, lo, hi) => Math.min(hi, Math.max(lo, v));

// drag out past the right edge -> clientX huge -> frac > 1 -> clamp back to 100
setPos(clamp(pctFromEvent(e), 0, 100));
    
      
    6. 
      
  6. 
        
    6
    One setPos writes everything
    
        
    There is a single source of truth — pos — and one function that applies it. setPos clamps, stores, then fans out: the clip-path on the top layer, the divider's left, the handle's aria-valuenow, the in-frame % pill, and (via a callback) the read-out card. Because every input funnels through here, the picture, the ARIA and the read-out can never disagree.
    
        
    function setPos(p, src){
  pos = clamp(p, 0, 100);
  before.style.clipPath = `inset(0 ${100 - pos}% 0 0)`;   // the wipe
  divider.style.left    = pos + '%';                      // line + handle
  const r = Math.round(pos);
  handle.setAttribute('aria-valuenow', r);
  handle.setAttribute('aria-valuetext', r + '% before, ' + (100 - r) + '% after');
  readout.textContent = r + '%';
  onChange && onChange(pos, src);                          // the read-out card
}
    
      
    7. 
      
  7. 
        
    7
    Drag once, for mouse and touch
    
        
    Pointer events unify mouse, touch and pen, so one set of handlers covers all input. On pointerdown we call setPointerCapture so every later move/up routes to the stage even if the finger slides outside it — the drag never "sticks". touch-action:none on the stage stops the browser from scrolling the page mid-drag on touch.
    
        
    let dragging = false;
stage.addEventListener('pointerdown', e => {
  dragging = true;
  stage.setPointerCapture(e.pointerId);     // keep events even outside the box
  setPos(pctFromEvent(e), 'drag');
});
stage.addEventListener('pointermove', e => { if (dragging) setPos(pctFromEvent(e), 'drag'); });
stage.addEventListener('pointerup',   () => { dragging = false; });
stage.addEventListener('pointercancel', () => { dragging = false; });
    
      
    8. 
      
  8. 
        
    8
    The handle is a real slider
    
        
    Give the handle role="slider" with aria-valuemin/max/now and a tabindex, and it becomes an assistive-tech slider for free. On keydown, ←/→ nudge one percent, Shift or PageUp/Down jump ten, and Home/End snap to the edges — each just calls the same setPos. preventDefault stops the arrows from scrolling the page.
    
        
    handle.addEventListener('keydown', e => {
  const step = e.shiftKey ? 10 : 1; let done = true;
  if      (e.key === 'ArrowRight' || e.key === 'ArrowUp')   setPos(pos + step, 'keyboard');
  else if (e.key === 'ArrowLeft'  || e.key === 'ArrowDown') setPos(pos - step, 'keyboard');
  else if (e.key === 'PageUp')   setPos(pos + 10, 'keyboard');
  else if (e.key === 'PageDown') setPos(pos - 10, 'keyboard');
  else if (e.key === 'Home')     setPos(0,   'keyboard');
  else if (e.key === 'End')      setPos(100, 'keyboard');
  else done = false;
  if (done) e.preventDefault();
});

  9. 
        
    9
    Flip the axis for the horizontal variant
    
        
    A horizontal divider is not a new component — it is the same code with one flag. When orient === 'h', read clientY against the stage height, clip the bottom instead of the right with inset(0 0 (100−pos)% 0), and move the divider's top rather than its left. The arrow keys and everything else are untouched.
    
        
    const vertical = orient === 'v';

function pctFromEvent(e){
  const r = stage.getBoundingClientRect();
  const frac = vertical ? (e.clientX - r.left) / r.width
                        : (e.clientY - r.top)  / r.height;   // Y instead of X
  return clamp(frac * 100, 0, 100);
}
// in setPos:
before.style.clipPath = vertical ? `inset(0 ${100-pos}% 0 0)`   // trim right
                                 : `inset(0 0 ${100-pos}% 0)`;  // trim bottom
divider.style[vertical ? 'left' : 'top'] = pos + '%';

  10. 
        
    10
    Accessibility & the read-out
    
        
    The handle carries role="slider", live aria-valuenow and a spoken aria-valuetext ("70% before, 30% after"); its aria-orientation matches the axis it moves along. Decorative bits (the chevrons, the corner tags) are aria-hidden. The read-out card is a pure reader of pos — a split meter and a few pills — so it is impossible for the numbers to drift from the wipe.
    
        
    // value axis: a vertical divider slides horizontally, and vice-versa
handle.setAttribute('aria-orientation', vertical ? 'horizontal' : 'vertical');
handle.setAttribute('aria-valuetext', r + '% before, ' + (100 - r) + '% after');

function paintReadout(pos){                 // the card only READS pos
  const r = Math.round(pos);
  meterBefore.style.width = r + '%';
  meterAfter.style.width  = (100 - r) + '%';
  pPos.textContent = r + '%';
}
