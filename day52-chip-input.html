DesignFromZero · Day 52

Chip / Tag Input — one control that is a text box and a list at the same time. Type a word and press Enter or , and it hardens into a removable chip; Backspace on an empty field eats the last one; ← walks into the chips to navigate and delete; the × on any chip removes it; a paste splits on commas into many chips at once. It rejects duplicates, enforces a max, can validate each entry (e.g. emails), and offers an autocomplete list as a real combobox + listbox. Built from a plain <input> and an array, wired with aria-expanded, aria-activedescendant and a live region — the multi-value field behind every tag picker, recipient box and label editor, rebuilt from scratch in one file.

Type, comma, Enter — words become removable chips.

A chip input lets someone enter many values in one field — tags, skills, recipients, labels. Each committed value becomes a small chip with an ×; the caret keeps sitting after them, ready for the next. Try it: type a word and hit Enter or ,; paste alpha, beta, gamma to add three at once; press Backspace in the empty box to delete the last; press ← to step into the chips and ←→ between them, Delete to remove; click any ×. Use the controls to toggle the autocomplete list, allow or block duplicates, switch validation to email, and dial the max. The panel on the right shows the exact values array the form would submit.

    Gmail’s recipient box, GitHub’s label picker, Stack Overflow’s tag field, every “add skills” form — the same control each time: a text box that yields a list. Keep the rules obvious — a clear commit key (Enter / comma), a visible remove affordance, paste that splits, quiet dedup and a firm max, honest validation with a spoken reason — and wire the a11y: a real input, a combobox for suggestions, focus you can drive into the chips, and a live region for what just happened. Get those and the multi-value field feels effortless instead of fiddly.

    🔨 Build it yourself
    
    
    A chip input is a text field and a list fused into one control. We start from the markup — a bordered box with chips and an input inside — make it look and focus like a single field, add the commit keys that turn text into a chip, wire removal by × and by Backspace, split a paste on commas, add dedup + max, plug in validation, build the autocomplete combobox, drive keyboard navigation into the chips, and finish with the a11y & live region. Vanilla HTML, CSS and JS — no framework, no dependencies.
    
    
      
      
    1. 
        
      1
      The markup — chips and an input in one box
      
        
      The whole control is a flex container that wraps: zero or more chips followed by a single text <input> that flexes to fill the last line. The input is the only real form field; the chips are decoration around an array you keep in JS. Mark the box role="group" and give the input a real aria-label.
      
        
      <div class="chip-field" role="group" aria-label="Tags">
  <!-- chips are injected here, before the input -->
  <input class="chip-input" type="text"
         aria-label="Add a tag"
         placeholder="Type a tag and press Enter…"
         autocomplete="off" />
</div>

let chips = [];   // the single source of truth

    2. 
        
      2
      Make it look and focus like a single field
      
        
      Two tricks sell the illusion. First, cursor:text plus a click handler focuses the input whenever the padding is clicked — the whole box behaves like an input. Second, :focus-within draws the focus ring on the container, so tabbing to the inner input lights up the whole field. Style chips as pill badges that wrap onto new lines.
      
        
      .chip-field { display:flex; flex-wrap:wrap; gap:8px;
  align-items:center; padding:9px 10px; border:1.5px solid #e2e8f0;
  border-radius:14px; cursor:text; }
.chip-field:focus-within { border-color:#a5b4fc;
  box-shadow:0 0 0 4px rgba(99,102,241,.16); }

chipField.addEventListener('mousedown', e => {
  if (e.target === chipField){ e.preventDefault(); input.focus(); }
});
      
      
      3. 
      
    3. 
        
      3
      Commit — text becomes a chip
      
        
      A keystroke turns the current text into a chip. The commit keys are Enter and , (a comma should never end up inside a chip). One commit() function is the single funnel: everything — typing, pasting, picking a suggestion — goes through it, so the rules live in exactly one place. After a successful add, clear the input and re-render.
      
        
      input.addEventListener('keydown', e => {
  if (e.key === 'Enter' || e.key === ','){
    e.preventDefault();          // comma must not land in the text
    commit(input.value);
  }
});

function commit(raw){
  splitParts(raw).forEach(tryAdd);   // steps 5-7 do the work
  input.value = '';
  renderChips();
}
      
      
      4. 
      
    4. 
        
      4
      Remove — the × and Backspace
      
        
      Two removal paths. Every chip carries a real <button> with a × and an aria-label="Remove {value}" — click it and the chip at that index is spliced out. And the classic: pressing Backspace while the input is empty deletes the last chip, so a fast typist never has to reach for the mouse. Both call the same removeChip(i).
      
        
      function removeChip(i){
  chips.splice(i, 1);
  renderChips();
}

input.addEventListener('keydown', e => {
  if (e.key === 'Backspace' && input.value === '' && chips.length){
    removeChip(chips.length - 1);   // eat the last chip
  }
});

// each chip: <button aria-label="Remove ${v}">&times;</button>
      
      
      5. 
      
    5. 
        
      5
      Paste — split on commas into many chips
      
        
      People paste alice, bob, carol or a column of newline-separated values. Intercept the paste event, read the clipboard text, and if it contains a comma or newline, split it and feed every piece through commit(). The same splitParts() splitter is reused by the Enter/comma path, so typing and pasting behave identically.
      
        
      const splitParts = raw => raw.split(/[,\n]/);   // comma OR newline

input.addEventListener('paste', e => {
  const text = (e.clipboardData || window.clipboardData).getData('text');
  if (/[,\n]/.test(text)){
    e.preventDefault();
    commit(input.value + text);   // prepend whatever was typed
  }
});
      
      
      6. 
      
    6. 
        
      6
      Dedup & max — the gatekeepers
      
        
      Before a value becomes a chip it must pass the gates. Trim it and drop empties. Unless duplicates are explicitly allowed, reject a value already present (compare case-insensitively). And never exceed the max. Each rejection returns a reason so the UI can explain itself instead of silently swallowing input.
      
        
      function tryAdd(v){
  v = v.trim();
  if (!v) return { ok:false };
  if (chips.length >= cfg.max)
    return { ok:false, reason:`Max ${cfg.max} tags reached` };
  if (!cfg.allowDup &&
      chips.some(c => c.toLowerCase() === v.toLowerCase()))
    return { ok:false, reason:`"${v}" is already added` };
  chips.push(v);
  return { ok:true };
}
      
      
      7. 
      
    7. 
        
      7
      Validation — e.g. email chips
      
        
      Sometimes a chip must match a shape — an email, a hashtag, a positive number. Add one more gate: if the field is in email mode, test the value against a simple regex and reject with a reason if it fails. On rejection, shake the field and speak the message through the live region — feedback the user can both see and hear.
      
        
      const EMAIL = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

// inside tryAdd, before the dedup check:
if (cfg.mode === 'email' && !EMAIL.test(v))
  return { ok:false, reason:`"${v}" is not a valid email` };

function reject(reason){
  setMsg(reason, 'err');                 // aria-live announces it
  field.classList.add('shake');
  setTimeout(() => field.classList.remove('shake'), 320);
}

      8
      Autocomplete — a combobox + listbox
      
        
      Suggestions are an ARIA combobox: the input gets role="combobox", aria-expanded and aria-controls pointing at a role="listbox". On input, filter a pool by the typed text (minus what is already chosen), render role="option" rows, and track the highlighted one with aria-activedescendant — not real focus, which stays in the input so typing never breaks. ↓↑ move the highlight, Enter picks it.
      
        
      <input role="combobox" aria-expanded="false"
       aria-autocomplete="list" aria-controls="list">
<ul id="list" role="listbox"></ul>

function updateSuggest(){
  const q = input.value.trim().toLowerCase();
  items = POOL.filter(s => s.toLowerCase().includes(q)
              && !chips.includes(s)).slice(0, cfg.maxSug);
  input.setAttribute('aria-expanded', String(items.length > 0));
  // highlight moves via aria-activedescendant, focus stays put
}
      
      
      9. 
      
    9. 
        
      9
      Keyboard nav — step into the chips
      
        
      The mouse can click any ×; the keyboard needs a way in. When the caret is at the start of an empty input, ← moves focus onto the last chip. From a chip, ←→ roam (roving tabindex), Delete/Backspace removes it and lands focus on a neighbour, and → past the end — or Esc — returns to the input. Now every chip is reachable without a pointer.
      
        
      input.addEventListener('keydown', e => {
  if (e.key === 'ArrowLeft' && input.selectionStart === 0
      && chips.length) focusChip(chips.length - 1);
});

function onChipKey(e, i){
  if (e.key === 'ArrowLeft')  focusChip(i - 1);
  if (e.key === 'ArrowRight') i + 1 < chips.length ? focusChip(i+1) : input.focus();
  if (e.key === 'Delete' || e.key === 'Backspace'){ removeChip(i); }
  if (e.key === 'Escape') input.focus();
}

      10
      A11y, the live region & when to use one
      
        
      Announce changes: an aria-live="polite" status says “Added 3 tags” or the rejection reason so non-sighted users are never left guessing. Build chip labels with textContent, never innerHTML, so a pasted <script> is inert. Use a chip input when values are short, many and equal — tags, recipients, labels. If there is only ever one value, use a plain input; if the set is fixed and small, checkboxes or a multiselect may read clearer.
      
        
      <div role="status" aria-live="polite" id="msg"></div>

// safe render — user text can never become markup
const label = document.createElement('span');
label.textContent = value;          // NOT innerHTML

// GOOD: many short equal values
[ design, frontend, a11y, css ]     // tags / recipients / labels
// AVOID: one value -> plain input; fixed small set -> checkboxes
