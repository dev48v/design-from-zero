DesignFromZero · Day 58

macOS Finder — a real file browser driven by one in-memory tree. A plain nested-object virtual filesystem (folders with children, files with size / modified / kind) is decorated once with parent pointers, so the entire application state collapses to a single node — current — and everything else is derived: the breadcrumb is the parent-chain of current, and Back / Forward are just a history array + index of the nodes you have visited. That one folder feeds three renderers of the same data: an icon grid of drawn glyphs, a list table whose Name / Date / Size / Kind columns sort on click, and a Miller column view that maps chainOf(current) to a row of panes and pushes a new pane to the right every time you drill deeper. Single click selects (blue highlight), double-click a folder opens it, the sidebar Favourites jump straight to Applications / Desktop / Documents / Downloads while Recents and AirDrop are synthetic pseudo-nodes that flow through the same code path. Traffic-light window controls, a live read-out of the derived state, no libraries, no external images — every icon is inline SVG.

One tree, one current node — three views that render it three ways.

Everything you see below is drawn from a single nested-object filesystem. Double-click a folder to open it, use ← → in the toolbar to walk your history, click a breadcrumb to jump up, or pick a Favourite in the sidebar. Flip between Icon, List and Column with the switch on the right of the toolbar — the same folder, re-rendered. Click a column header in List view to sort. The card on the right is a pure read-out of the derived state.

Live state — all derived from current

There is no per-view state. current is the only source of truth — the breadcrumb, the three renderers and Back/Forward all read from it, so they can never disagree.

Every file browser — Finder, Explorer, the picker in your IDE — is this same shape: a tree of nodes, a pointer to the current one, a history of where you have been, and one or more renderers that turn a folder's children into rows. Get the model right and Icon / List / Column are not three features — they are three functions of the same data.

🔨 Build it yourself

    
Finder looks like a lot of UI, but it is one tree and one pointer. We define the virtual filesystem, wire parent pointers so any node knows its ancestors, keep the whole app state as a single current node, derive the breadcrumb from its parent-chain, add a history stack for Back / Forward, then write the three renderers — icon grid, sortable list, Miller columns — that all read the same folder. Selection, double-click-to-open and the sidebar favourites fall out of the same model. Vanilla HTML, CSS and JS — no framework, no dependencies, no images.

    The virtual filesystem is a nested object
    
        
    A folder is a node with a children array; a file is a leaf with size, modified and kind. That is the entire data model — a tree of plain objects. Everything the browser shows is a projection of this one structure.
    
        
    const VFS = {
  name:"devanshu", kind:"folder", children:[
    { name:"Documents", kind:"folder", children:[
      { name:"resume.pdf", kind:"PDF document", size:284000, modified:"2026-07-22 14:23" },
      { name:"Work", kind:"folder", children:[ /* ... */ ] }
    ]},
    { name:"Downloads", kind:"folder", children:[ /* ... */ ] }
  ]
};

    2
    Parent pointers — so a node knows where it is
    
        
    Walk the tree once and hang a non-enumerable parent off every child. Now any node can trace its way back to the root, which is what makes the breadcrumb and the column view almost free. chainOf(node) just climbs those pointers.
    
        
    (function link(node, parent){
  node.parent = parent || null;
  (node.children || []).forEach(c => link(c, node));
})(VFS, null);

function chainOf(node){                 // root ... node
  const a = []; for (let n = node; n; n = n.parent) a.unshift(n); return a;
}

    3
    One pointer is the whole state
    
        
    The app has almost no state: current (the open folder), view, sel (the highlighted item) and a sort. A single render() reads current and repaints the breadcrumb, the chosen view and the status bar. Change current, call render(), done.
    
        
    const state = { current: VFS, view:"icon", sel:null, sort:{ key:"name", dir:1 } };

function render(){
  renderCrumbs();                 // from chainOf(current)
  renderStatus();                 // "N items"
  ({ icon:renderIcon, list:renderList, column:renderColumn })[state.view]();
}

  4. 
        
    4
    Navigate + a history stack for Back / Forward
    
        
    go(node) sets current and pushes it onto a history array, truncating any forward entries first (exactly like a browser). Back and Forward just move an index and read the node back out — no re-computation, because a node fully describes a location.
    
        
    let history = [VFS], hi = 0;
function go(node){
  if (node === state.current) return;
  history = history.slice(0, hi + 1);   // drop the forward branch
  history.push(node); hi = history.length - 1;
  state.current = node; state.sel = null; render();
}
function back(){    if (hi > 0)                 { state.current = history[--hi]; state.sel = null; render(); } }
function forward(){ if (hi < history.length-1) { state.current = history[++hi]; state.sel = null; render(); } }

    5
    The breadcrumb is just the parent-chain
    
        
    No separate breadcrumb state to keep in sync — map chainOf(current) to buttons, each of which calls go() on its node. Clicking “Documents” in the trail jumps straight up to it. The trail is always correct because it is computed, never stored.
    
        
    function renderCrumbs(){
  crumbsEl.innerHTML = "";
  chainOf(state.current).forEach((node, i, arr) => {
    if (i) crumbsEl.append(sep("\u203a"));      // › separator
    const b = document.createElement("button");
    b.textContent = node.name;
    b.onclick = () => go(node);
    crumbsEl.append(b);
  });
}

    6
    Renderer #1 — the icon grid
    
        
    Lay current.children into a CSS grid of tiles. Each tile is a drawn SVG glyph plus a name label. Single click sets state.sel and re-renders (blue label); double-click a folder calls go() to open it. Files ignore the double-click.
    
        
    function renderIcon(){
  main.innerHTML = "";
  const grid = el("div","mac-iconwrap");
  current.children.forEach(node => {
    const cell = el("div","mac-icon" + (node === state.sel ? " sel" : ""));
    cell.innerHTML = `<div class="gl">${iconSVG(node)}</div><div class="nm">${esc(node.name)}</div>`;
    cell.onclick    = () => { state.sel = node; render(); };
    cell.ondblclick = () => { if (isFolder(node)) go(node); };
    grid.append(cell);
  });
  main.append(grid);
}

    7
    Renderer #2 — the sortable list
    
        
    A table with Name / Date Modified / Size / Kind headers. Clicking a header sets state.sort.key (or flips dir if it is already the key). The comparator keeps folders grouped, then orders by the chosen field, and an arrow shows the direction. Same rows, re-ordered.
    
        
    function sorted(items){
  const { key, dir } = state.sort;
  return [...items].sort((a,b) => {
    if (isFolder(a) !== isFolder(b)) return isFolder(a) ? -1 : 1;   // folders first
    let av = key === "size" ? (a.size||0) : (a[key] ?? a.name).toString().toLowerCase();
    let bv = key === "size" ? (b.size||0) : (b[key] ?? b.name).toString().toLowerCase();
    return (av < bv ? -1 : av > bv ? 1 : 0) * dir;
  });
}
function onHeader(key){
  if (state.sort.key === key) state.sort.dir *= -1;      // toggle direction
  else state.sort = { key, dir:1 };                      // new column, ascending
  render();
}

    8
    Renderer #3 — Miller columns
    
        
    This is where parent pointers pay off. chainOf(current) is the list of open folders; render one pane per folder, each showing that folder's children, and highlight the child that leads to the next pane. Click a folder in any pane and go() makes the chain longer — so a new pane appears to the right. Click a file and a preview pane replaces the tail.
    
        
    function renderColumn(){
  const chain = chainOf(state.current);            // folders currently open
  const wrap  = el("div","mac-cols");
  chain.forEach((folder, i) => {
    const next = chain[i + 1];                      // the folder drilled into
    const col  = el("div","mac-col");
    folder.children.forEach(node => {
      const row = el("div","mac-col-row" +
        (node === next ? " lead" : node === state.sel ? " sel" : ""));
      row.innerHTML = `${iconSVG(node)}<span class="nm">${esc(node.name)}</span>` +
                      (isFolder(node) ? `<span class="chev">\u203a</span>` : "");
      row.onclick = () => isFolder(node) ? go(node) : selectFile(node);
      col.append(row);
    });
    wrap.append(col);
  });
  if (state.sel && !isFolder(state.sel)) wrap.append(previewPane(state.sel));
  main.append(wrap);
  main.scrollLeft = main.scrollWidth;               // keep the newest pane in view
}

    9
    Icons are drawn, not downloaded
    
        
    No image files. A folder is one blue SVG path; an app is a coloured squircle with an initial; a document is a page-with-a-folded-corner tinted by kind, carrying a three-letter tag (PDF, TXT, ZIP…). One iconSVG(node) switch returns the right markup, so every view shares the same glyphs.
    
        
    function iconSVG(node){
  if (isFolder(node)) return FOLDER_SVG;
  if (node.kind === "Application") return appSVG(node);      // squircle + initial
  if (/image/.test(node.kind))     return imageSVG(node);    // little photo
  return docSVG(tagFor(node.kind), colorFor(node.kind));     // page + folded corner + tag
}

    10
    Sidebar favourites & synthetic pseudo-nodes
    
        
    Applications / Desktop / Documents / Downloads are just go(lookup(path)). Recents and AirDrop are not in the tree — they are pseudo-nodes built on the fly. Recents is a folder whose children are the newest files gathered by walking the whole tree, so it flows through the same renderers unchanged; AirDrop carries a special kind the renderer draws as device pucks. New sources cost a node, not a new code path.
    
        
    function allFiles(node, out=[]){
  (node.children||[]).forEach(c => isFolder(c) ? allFiles(c, out) : out.push(c));
  return out;
}
const RECENTS = { name:"Recents", kind:"folder", synthetic:true,
  children: allFiles(VFS).sort((a,b) => b.modified.localeCompare(a.modified)).slice(0,12) };
const AIRDROP = { name:"AirDrop", kind:"airdrop", synthetic:true, children:[] };
// sidebar click → go(RECENTS) / go(AIRDROP) / go(lookup("Documents"))

✅ Day 58 of DesignFromZero done — macOS Finder.
You built a working file browser from a nested-object tree and a single current pointer. Parent pointers made chainOf() trivial, which handed you the breadcrumb and the Miller columns for free; a history array + index gave real Back / Forward; and one render() drove three views of the same folder — an icon grid, a sortable list and drill-right columns. Selection and double-click-to-open are two event handlers, the sidebar is go() calls, and even Recents / AirDrop are just pseudo-nodes that reuse every renderer. Every icon is inline SVG. 👋 Model the data as a tree with a pointer, and the UI becomes a set of pure functions of that state.
